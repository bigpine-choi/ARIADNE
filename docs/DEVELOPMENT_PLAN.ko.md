# ARIADNE 개발 계획

기준일: 2026-10-01, Asia/Seoul

상태: 로컬 수집·보고 코드 구현 이후의 개발 계획. 현재 구현·검증 결과와 후속 목표를 구분하며 자동 보고 운영은 아직 비활성이다.

## 1. 개발 방향과 실사용 목표

**웹 기반 업무 운영체계를 먼저 완성하고, Godot은 같은 업무 API를 사용하는 선택적 후속 클라이언트로 개발한다.** 기존 Godot 우선 검증 계획과 고정 6주·12주 일정은 이 계획으로 대체한다. 아래 버전은 달력상 납기가 아니라 의존성과 완료조건으로 정한 개발 순서다.

현재 첫 연결 흐름은 공유 폴더 변경 보관과 본인 Outlook COM 수집이다. 개인 주간보고의 생성·발송 코드는 연결했으며 원천 완전성·AI 품질·예약 운영 확인이 남아 있다. 업무 관리의 다음 실사용 목표는 메일에서 처리할 일·기다릴 일·근거를 연결하고, 사용자가 수정한 업무 상태를 재분석과 재실행 후에도 보존하는 것이다. 이어 확정된 업무정보로 운용지시서·기안문·메일 초안을 함께 준비한다.

한솔님의 검토·입력·재탐색 시간이 실제로 줄어드는지 평가한다. 금액·이자·보수·분배 계산은 검증된 코드와 엑셀 수식이 담당하고, AI는 문서 해석·근거 검색·분류와 초안을 담당한다. 최종 형태는 팀이 공유하는 한국어 중심 웹 대시보드이며 데스크톱 업무환경을 우선한다.

## 2. 현재 구현 상태와 시작 자료

- **main 구현:** foundation Python 모델·SQLite·HTTP 서버를 재사용하고 파일 버전 관리·업무 조회 웹, Outlook COM, Teams 제한 복사, 개인 주간보고 및 예약 등록 도구를 연결했다. 구체적인 현재 경로는 [구조 문서](ARCHITECTURE.ko.md), 실행법은 [로컬 자동화 안내](LOCAL_AUTOMATION.ko.md)에 있다. 웹 입력·수정 화면, MSG 파서, Graph·MCP, 팀 권한과 계약 일정·운용지시 패키지는 미구현이다.
- **재사용 기준:** [foundation 고정 커밋 `14f47c8`](https://github.com/bigpine-choi/ARIADNE/tree/14f47c8ab02a60cb266837041ab0b797f4adb719)의 Python 부분을 선별 통합했다. Godot 클라이언트는 그 브랜치에 남아 있다. 전체 브랜치를 병합한 것은 아니다.
- **검증:** 기존 42개·신규 28개 테스트와 Windows·Ubuntu/Python 3.12·3.14 CI가 통과했다. 실제 파일 59개 저장·재비교·바이트 일치, 본인 메일 110건 수집·재수집 중복 방지를 확인했다. Teams의 개별 복사·이동은 확인했으나 수집기 전체·작성자·날짜·전체 주간 이력은 미검증이다.
- **운영 상태:** API 키가 없어 실제 모델 호출·보고 품질·실메일 발송·예약 등록은 수행하지 않았다. `enabled`, `auto_send`, `allow_partial_report`는 기본 false다. 테스트 성공을 운영 활성화로 보고하지 않는다.
- **이전 자료 점검:** 초기 백서의 ZIP 5개·MSG 523개와 이후 계획 점검의 ZIP 4개·MSG 385개·회의 Excel 3개는 각각 당시의 목록·자료 집계다. MSG 본문·첨부 전수 분석이나 정답 라벨링 결과가 아니며 현재 파일 59개·메일 110건과 합산하지 않는다.
- 당시 「6월 넷째주 받은 메일함.zip」은 미전달 상태였다. 과거 ZIP 분석을 재개할 때 가용성·해시·항목 수·중복을 새로 확인하고 수집 공백을 표시한다.
- 과거 자료에는 분석 기준시각과 수집 범위를 표시한다. 과거 회신 대기를 현재 미처리로 단정하지 않는다. 계약 일정 검증에는 최종 날인 계약서·변경계약 표본이 별도로 필요하다.

원본은 수정·삭제하지 않는다. 회사 메일·계약·개인정보는 Git에 넣지 않으며 자동 테스트에는 합성 사례를 사용한다. 실제 자료 평가는 허용된 별도 환경에서 수행한다.

## 3. 자동화 기능과 실행 경계

| 기능 | 자동화할 결과 | 사람이 확인·확정할 사항 |
| --- | --- | --- |
| 메일·첨부 업무 추출 | 펀드·요청·담당·기한·선행조건·회신 필요 여부, 중복 업무 연결 | 연결 모호성, 담당 미지정, 날짜·금액 충돌 |
| 미결·누락 탐지 | 회신 없는 요청, 근거 없는 완료, 담당 공백, 임박한 준비 업무 | 누락된 자료와 예외 사유 |
| 계약 의무·일정 | 정기결산·분배·보수·보고·이자·만기·조건부 의무의 준비일·마감일 | 문서 효력, 변경 충돌, 최초 일정 규칙 |
| 자금집행 준비 패키지 | 기존 양식의 운용지시서 XLSX, 날인 기안문, 내용을 요약한 메일 초안 | 지급일·금액·계좌·증빙·최종 승인 |
| 금액·문서 대사 | 요청서·분개장·운용지시서의 불일치·중복 후보 | 차이 원인과 정정 처리 |
| LP·주간보고 | 근거 연결된 보고 양식, 국·영문 회신 초안, 실제 업무 단위 활동·미결 요약 | 보고 수치와 판단 의견, 공유 대상 |
| 날인·집행·신고 추적 | 요청→회신→증빙 수령→검토의 진행 이력 | 완료조건 충족과 최종 검토 |
| 승인 후 제한적 실행 | 허용된 연결에서 승인한 요청 실행·결과 재조회·실패 추적 | 실행별 대상·내용·첨부·유효한 승인 |

메일 발송과 파일 도착만으로 업무를 완료 처리하지 않는다. 날인본 도착은 원칙적으로 ‘검토 필요’이며 서명·날인·첨부 검토가 완료돼야 ‘완료’로 전환한다. 불명확하면 ‘완료 추정’ 또는 ‘확인 필요’를 판단 표시로 붙인다.

현재 개인 주간보고 발송은 설정한 본인 계정만 대상으로 하는 별도 경로다. 실행·자동 발송을 명시적으로 켜야 하며 현재 운영은 비활성이다. 임의 수신자 발송·일정 변경·운용지시 제출·자금집행은 향후 승인·권한 기능을 거친다. 원본 삭제·변경 기능은 없다. 계획 승인·문서 생성·MCP 연결 자체는 새로운 외부 실행 승인이 아니다.

## 4. 데이터와 판단 원칙

사용자에게 표시하는 업무 상태는 **신규, 검토 필요, 진행 중, 내부 승인 대기, 외부 회신 대기, 일정 확정 대기, 완료, 보류, 기한 초과, 재개, 취소**를 유지한다. ‘기한 초과’는 마감일·분석 기준시각·종료 여부로 계산하는 별도 위험 표시로 구현해 ‘외부 회신 대기 + 기한 초과’를 함께 보존한다. ‘완료 추정’과 ‘확인 필요’도 확정 완료 상태와 분리한다.

원본, 파싱 결과, AI 추출·제안, 사용자 확정값, 업무·일정의 현재값을 구분한다. 화면별로 업무를 복제하지 않는다. 핵심 데이터와 변경 방식은 [코드·데이터 구조](ARCHITECTURE.ko.md)를 따른다.

- 근거에는 원천 식별자·해시·버전·접근권한, 메일·스레드·첨부 관계, 문서 페이지·조항 또는 엑셀 시트·셀 위치를 연결한다.
- 업무에는 펀드·자산·담당자·관계기관·기한·선행조건·필요자료·완료조건을 연결한다. 펀드의 한글명·영문명·약칭·SPC는 식별자와 별칭으로 연결한다.
- AI 제안에는 모델·프롬프트·스키마·규칙 버전과 부족한 근거를 남긴다. 신뢰도 높음·보통·낮음은 검토 신호이며 정답 확률이나 실행 권한이 아니다.
- 사용자 확정값은 재분석이 덮어쓰지 않는다. 새 근거와 충돌하면 이전값·제안값·차이·근거를 함께 보인다. 변경에는 시각·주체·이전값·새값·근거·사유를 기록한다.
- 제목만으로 병합하지 않는다. 스레드·인용문·본문·첨부·상대방·시각을 비교하고 여러 펀드·요청이 있는 메일은 실제 관리 가능한 업무 단위로 나눈다.
- 원문에 없는 날짜·금액·담당·반복주기를 확정하지 않는다. 날짜만 있는 기한은 Asia/Seoul 날짜로 보존하고 월말·윤년·영업일·사건 의존 계산은 확정 규칙과 달력으로 수행한다.

**미래 의무:** 최종 날인 정관·신탁계약·약정과 유효한 변경계약을 함께 읽어 현행 조건을 구성한다. 변경의 적용 조항·효력 발생일을 확인하며 원계약이 더 앞선 순위라는 이유로 변경을 무시하지 않는다. 이후 공식 동의·결의, 관계기관 확정 안내, 주간회의·내부 메모, AI 추정 순으로 검토한다.

**실제 완료:** 지급내역·날인본·제출확인 등 업무별 직접 증거, 상대방 수령·승인·처리 완료 회신, 발신 메일·첨부, 내부 기안·주간회의, AI 추정 순으로 검토한다. 운용지시서는 지시 발행의 근거가 될 수 있지만 실제 지급 완료에는 해당 완료조건에 맞는 증거가 필요하다.

자료 충돌은 최신성·날인 여부·효력·작성 주체를 비교하고 차이를 표시한다. 임의 선택하지 않는다. 우선순위는 계약상 기한·자금 영향·투자자 대응·승인·선행조건·지연 위험·재촉·담당 공백으로 정한다.

## 5. OpenAI API·MCP·Graph의 역할

| 구성 | ARIADNE에 적용할 역할 | 구현 시 경계 |
| --- | --- | --- |
| Outlook COM·Teams 로컬 복사 | 회사 PC의 기존 로그인 세션에서 수신/발신 및 지정 대화 본문 읽기 | 현재 구현. Outlook은 본인 받은·보낸 편지함 범위, Teams는 항상 불완전 수집 |
| Responses API + Structured Outputs | 메일·문서에서 업무·근거·불확실성을 정해진 스키마로 추출 | 스키마 준수는 사실성 보장이 아님. 규칙 검사 후 반영 |
| Function Calling | 검색·계산·문서 작성 등 허용된 업무 함수를 호출 | 입력 검증·권한·승인·중복 방지는 서버에서 검사 |
| Outlook MCP/커넥터 | 필요한 메일 검색·조회와 초기 읽기 전용 연결 실험 | 인증·테넌트 정책·실제 노출 도구 확인. 첨부 원본 제공을 가정하지 않음 |
| Microsoft Graph | 수신·발신 및 지정 하위 폴더의 지속적 증분 수집 | 폴더별 delta·페이지·체크포인트·재시도·접근 누락 관리 |
| RAG / File Search | 권한·펀드·문서 버전으로 좁힌 뒤 계약·메일 근거 검색 | 검색 결과를 전수 목록으로 취급하지 않음. 현행 문서와 원문 위치 검증 |
| ARIADNE MCP 서버 | 자체 근거 검색·업무 조회·문서 준비 기능을 AI 클라이언트에 제공 | Outlook을 읽는 연결과 별개. 공통 업무 서비스를 재사용 |
| 작업 큐·스케줄러 / Agents SDK | 비동기 수집·분석·문서 생성, 다단계 도구 실행 | DB가 대기·승인·재시도 상태를 보존. SDK 도입은 복잡도에 따라 결정 |
| Batch API / Evals | 과거 자료 일괄 분석, 모델·프롬프트 변경 평가 | 비용·비동기 처리 적합성을 검증하고 정답 사례와 대조 |

MCP는 연결 규격이며 자체적으로 계정 권한·영구 동기화·정확성을 제공하지 않는다. 현재 회사 PC 수집은 MCP·Graph에 의존하지 않는다. 향후 Outlook API 커넥터와 ChatGPT 앱을 연결할 때 인증·가용 도구가 같다고 가정하지 않으며 회사 정책과 권한을 확인한다. 확보한 로컬 읽기 범위와 향후 MSG 가져오기는 별도로 관리한다.

코드는 **웹 화면 → 업무 API → 공통 업무 서비스·도메인 규칙**으로 나눈다. MSG·Graph·Outlook MCP·OpenAI·저장소·엑셀 생성기는 교체 가능한 어댑터로 둔다. UI와 worker의 수명도 분리한다. Godot을 추가해도 업무 규칙과 저장소를 별도로 구현하지 않는다.

계약 RAG와 문서 생성은 같은 근거·권한 계층을 사용한다. AI가 금액을 계산해 양식에 직접 쓰게 하지 않고, 확정 입력을 받은 계산·템플릿 함수가 산출물을 만든다. 자세한 모듈 경계·데이터 흐름·보안은 [ARCHITECTURE](ARCHITECTURE.ko.md), 실행할 작업은 [BACKLOG](BACKLOG.ko.md)에 둔다.

## 7. 화면 범위와 다음 개발 묶음

기본 메뉴는 다섯 개로 고정한다. v0.1~v0.2는 필요한 최소 화면만 연결하고 v0.5에서 완성한다.

1. **Command Center:** 오늘 할 일, 기한 초과, 신규 요청, 회신·승인 대기, 주요 위험 신호
2. **Calendar:** 과거 활동, 확정·예상·반복 일정, 펀드·담당자 필터
3. **Funds:** 기본정보·계약조건·관계기관·정기 일정·업무·활동·문서
4. **Work Queue:** 전체 업무, 상태·담당·기한·펀드·중요도 필터, 선행·후속 업무, 완료조건
5. **Evidence & Audit:** 근거 메일·문서, 변경·사용자 수정 이력, AI 추출·신뢰도, 충돌

현재 웹은 파일 관리·보고 상태·업무 조회까지만 제공한다. 다음 작업은 아래 순서로 관리한다.

1. Teams의 날짜·작성자·수집 범위를 확보할 승인된 경로를 확인한다. 부분 수집 초안을 사용할 경우 누락 표시와 자료 범위를 사용자와 확정한다.
2. 실행 환경의 API 키·모델을 설정하고 허용된 자료로 보고 근거·기간·누락·완료 표현·비용을 대조한다. 키 존재 여부만 확인하는 doctor를 실제 연결 검증으로 취급하지 않는다.
3. 검토한 개인 보고서의 본인 발송 접수·배달을 확인한 뒤 예약 작업을 등록하고 금요일 16시·절전 후 재개·실패 대사를 검증한다. 결과 불명 상태를 자동으로 재발송하지 않는다.
4. 기존 업무 API에 입력·상세·근거·상태 수정 웹 화면을 연결하고 메일→근거→업무 제안→사용자 확정→재실행 보존을 완성한다.
5. MSG 가져오기, 스레드·원천 간 식별, 회신·연기·취소·추가 증빙 평가를 진행한다. 계약·양식·팀 권한은 해당 단계 인수조건을 따로 충족한다.

로컬 수집과 가상 보고 테스트는 완료했지만 위 운영·품질 평가가 전체 로드맵 완료를 뜻하지 않는다.

## 8. 평가와 출시 기준

정답은 사용자 또는 업무 담당자가 확인한다. 동일 스레드와 같은 거래의 중복 자료를 개발용·최종 평가용 양쪽에 넣지 않는다. 스레드·업무 단위로 분리하고 시간순 검증을 추가해 미래 회신을 과거 판단에 사용하지 않는다. 특정 정확도 비율을 근거 없이 약속하지 않는다.

| 평가 영역 | 반드시 확인할 사례·기록 |
| --- | --- |
| 업무 추출·연결 | 중요한 요청 누락, 허위 업무, 잘못된 병합/분리, 다중 펀드·담당·전달·제목 변경을 각각 집계 |
| 완료·기한 | 발송만 존재, 첨부만 도착, 지시와 실제 지급 차이, 연기·취소·변경계약, 모호한 날짜·인용문 검사 |
| 근거·검색 | 원문 페이지·조항·시트·셀 재확인, 폐기/구버전 근거, 권한 밖 검색 결과, 근거 부족과 충돌 표시 |
| 수집의 완전성 | 페이지 경계·폴더 누락·접근 불가·첨부 미수집·부분 실패를 표시하고 수집 공백을 ‘업무 없음’으로 오판하지 않음 |
| 사용자 통제 | 확정값 무단 덮어쓰기 방지, 재분석 충돌 제안, 승인 후 내용 변경·승인 철회·동시 수정 검사 |
| 문서·계산 | 금액/단위/날짜/계좌 대사, 엑셀 수식·서식·숨김 상태 보존, 재계산·출력 확인, 누락 입력 차단 |
| 운영·복구 | 동일 자료 재수집·작업 재시도 중복 방지, 인증 만료·요청 제한·중단 후 재개, DB/파일 백업 복원 검사 |
| 보안·비용·효용 | 메일 내 악성 지시 격리, 권한·로그 노출 검사, 호출량·비용 기록, 수정·승인·입력·재탐색 포함 실제 소요시간 비교 |

근거 없는 완료·기한 확정, 사용자 확정값 무단 덮어쓰기, 권한 밖 노출과 중복 실행 사례는 출시 차단 결함으로 취급한다. 통과한 테스트가 실운영 무오류를 보장하지는 않는다. 표본 수·제외 사례·실패·모델/규칙 버전을 남기고 해당 업무 유형의 자동 반영 범위를 제한한다.

## 9. 운영·보안과 남은 결정

- 현재 COM과 Teams 로컬 수집은 기존 로그인 세션·접근 가능한 범위만 사용한다. 향후 Graph·Outlook MCP도 최소 권한과 회사 정책을 따른다. 읽기 권한과 외부 실행 권한은 분리한다.
- UI 종료와 서비스 중단을 구분한다. PC가 꺼진 동안의 상시 수집은 승인된 서버가 있어야 하며 재가동 시 누락 범위를 따라잡는다. 마지막 성공 시각과 오래된 데이터 경고를 표시한다.
- 외부 AI 전송 범위·보관·삭제·로그 정책과 비용 상한을 설정한다. 파일 업로드·검색 인덱스 보관은 호출 로그와 별도로 관리한다. 연결 실패나 AI 장애에도 수동 관리·확정 규칙 처리는 유지한다.
- 메일·첨부의 지시문은 자료로만 취급하며 앱 권한·승인·전송 대상을 바꿀 수 없다. 원문·운영 DB·토큰·개인정보는 코드·로그·공개 예제에 넣지 않는다.
- 승인된 저장 위치, 회사의 AI 전송 허용 범위와 Graph 권한, 계약 표본·영업일 기준, 팀 서버·인증·운영·복구 책임을 해당 버전 착수 전에 확인한다.

각 버전은 변경 목적, 기능, 데이터 구조 변화, 실제 검증 결과, 알려진 한계, 다음 과제를 기록한다. 선택 기술과 버전은 구현 시 확정하며 MCP·Agents SDK 도입 자체를 완료 목표로 삼지 않는다.
