# 오멘·회사 PC 운영 안내

ARIADNE의 실제 업무 시스템은 오멘에서 운영하고, 회사 PC는 공유폴더 수집·원본 보관·전달을 맡는다. 각 PC의 로컬 화면 주소는 동일한 http://127.0.0.1:8766/ 이지만 각자 자신의 DB를 사용한다.

| 기능 | PC | 한국시간 |
| --- | --- | --- |
| 회사 공유폴더 변경 버전 수집·암호화 전달 | 회사 PC | 평일 09~18시 정각 |
| 원본 파일 버전 목록 확정·전달 | 회사 PC | 금요일 16:00 |
| 회사 자료 수신·Outlook·하이웍스 수집 | 오멘 | 평일 09~18시 정각 |
| 지정 Teams 대화 수집 | 오멘 | 평일 12:00 한 번 |
| DB 근거의 AI 엑셀 생성·본인 메일 발송 | 오멘 | 금요일 16:15 |

같은 PC의 수집·보고는 순차 실행한다. 오멘이 이번 금요일 16시 보관본을 받지 못했으면 보고 생성·발송을 차단하고 이후 예약 실행에서 다시 확인한다. 보고 기간의 종료는 계속 16시다. 늦게 읽은 원본은 실제 관측 시각을 표시한다. 금요일 보고는 그 주 보관본의 파일 버전·양식을 사용하고 이후 변경된 파일을 섞지 않는다.

## 처음 시작

### 두 PC 모두 OneDrive 앱 없이 웹으로 연결

회사 PC와 오멘은 ‘회사 자료 전달 방식’에서 **회사 웹 OneDrive · 앱 설치 없이 전달**을 선택하고 같은 회사 ARIADNE 웹 폴더 주소를 저장한다. 배포용 프로필에 `company_web_url`을 지정하면 최초 설정에 미리 반영한다. ‘회사 웹 OneDrive 연결 열기’를 누르면 각 PC의 ARIADNE 전용 Edge 창이 열린다. 회사 계정 로그인·MFA는 사용자가 직접 완료한다. 회사 웹 폴더의 읽기 권한이 확인되면 연결 창이 닫히고 ARIADNE에 확인 시각이 표시된다. OneDrive 앱 연결·파일 탐색기 동기화 경로 입력은 필요 없다.

이후 회사 공유폴더의 보관·전달 버튼으로 실제 업로드를 확인한다. 예약은 같은 전용 브라우저의 로그인 상태로 화면을 표시하지 않고 전달하며 키보드·마우스를 조작하지 않는다. 로그인 만료·업로드 권한 부족·기업 브라우저 정책 제한은 실패로 표시하고 로컬 DB와 전달 파일을 보존한다. Windows 방화벽·회사 보안 프로그램·브라우저 정책은 변경하지 않는다. 웹 접근 자체가 제한되면 회사에서 허용한 연동 방법이 필요하다.

웹 대상은 연결 화면에 저장한 회사 SharePoint의 ARIADNE 폴더로 제한한다. 주소는 HTTPS 회사 `-my.sharepoint.com` 호스트와 `/personal/<계정>/Documents/ARIADNE` 형식만 허용하고, 전달 요청은 저장한 호스트·폴더를 벗어나지 않는다. 실제 회사 주소·사용자명은 로컬 설정에만 둔다. SharePoint REST의 같은 폴더에 `.ariadne-packet`만 업로드한다. 기존 파일은 덮어쓰거나 삭제하지 않는다. 같은 이름의 파일이 있으면 크기와 SHA-256을 확인하고, 업로드 후에도 원격 원본 바이트를 확인해야 전달 완료로 기록한다. 요청이 중간에 끊기면 다음 실행에서 기존 파일을 먼저 확인해 중복 업로드를 방지한다. 웹 전달의 파일당 제한은 64 MiB다.

오멘은 같은 웹 폴더의 암호화 파일만 읽어서 로컬 `incoming-packets`에 보관한 뒤, 인증 복호화·원본 해시·연속 순번을 확인하고 자기 DB에 반영한다. 웹 파일을 업로드·수정·삭제하지 않는다. 설치 ZIP 등 전달 파일이 아닌 파일은 읽지 않는다. 목록의 다음 페이지도 같은 호스트·같은 폴더만 허용한다. 한 실행에서 최대 20개를 순서대로 받고 남은 자료는 다음 실행에서 계속 받는다. 누락 순번·다른 발신 PC·변조·자료 연결 코드 오류는 자료 반영을 중단한다. 주간보고 직전에도 다시 수신하며 실패 또는 이번 금요일 보관본 미도착 시 AI 생성·발송을 차단한다.

최초 전달 순번을 이미 만든 설치에서 웹 방식으로 전환할 때는 기존 `.ariadne-packet` 파일 전부를 회사 데이터 폴더의 `outgoing-packets`로 복사해야 한다. 이전 순번이 없으면 뒤 순번의 전달을 중지한다. 코드·DB·암호화 키·전용 브라우저 프로필은 클라우드에 올리지 않는다.

개발 설치는 `pip install -e .[automation,cloud-web]`와 기존 Microsoft Edge가 필요하다. Windows 배포 ZIP에는 웹 연결 라이브러리를 포함하며 별도 브라우저를 내려받지 않는다. 연결·전달 검증에는 독립된 SharePoint 응답 모형을 사용한다. 실제 회사 로그인과 업로드는 현장에서 별도로 확인해야 한다.

1. Windows x64 배포 ZIP을 각 PC의 로컬 폴더에 압축 해제한다. ZIP 안에서 바로 실행하지 않는다. Python 설치·관리자 실행은 필요 없다. 회사 정책을 변경하거나 보안 프로그램을 끄지 않는다.
2. 회사 PC는 `2-회사PC-시작.cmd`, 오멘은 `1-OMEN-시작.cmd`를 연다. 실행 코드 폴더는 앞으로 이동하지 않는다. 예약이 그 경로를 사용한다.
3. 각 ARIADNE의 ‘연결 설정’에서 웹 전달 방식과 같은 회사 ARIADNE 웹 폴더 주소를 확인·저장한다. 사용자 배포본은 이 주소를 미리 넣을 수 있다.
4. 양쪽의 ‘회사 웹 OneDrive 연결 열기’로 전용 Edge 연결을 확인한다. 필요할 때만 회사 계정으로 직접 로그인한다. 이미 설정·연결된 회사 PC는 다시 설정하거나 새 DB를 만들지 않는다.
5. 회사 PC의 ‘오멘에 입력할 자료 연결 코드 준비’ → ‘자료 연결 코드 복사’. 오멘의 ‘회사 PC와 오멘 자료 연결’ 칸에 직접 붙여넣고 ‘자료 연결 저장’을 누른다. 코드를 채팅이나 동기화 파일에 넣지 않는다.
6. 회사 PC의 업무 자료에서 ‘공유폴더 보관·오멘 전달’을 실행한다. 오멘에서 ‘회사 회의 자료 받기’를 실행하고 파일 59개 등 실제 목록과 원본 시각을 확인한다. 연결 설정의 암호화 키 등록 여부만으로 전달 완료를 판단하지 않는다.
7. 오멘에서 classic Outlook의 회사 프로필과 Teams·하이웍스를 로그인한다. Outlook 데스크톱의 COM 자동화가 필요하며 웹 Outlook이나 새 Outlook만으로 대체되지 않는다. 메일 계정과 Teams 두 대화 이름을 확인한다. 다른 대화는 수집 범위에 넣지 않는다.
8. 오멘의 OpenAI 키를 처음 한 번 직접 저장한다. 회사 PC의 DPAPI 키는 다른 PC에서 사용할 수 없다. 이후 오멘에서는 자동 재사용한다.
9. 오멘에 설치한 하이웍스 확장을 **오멘의** 브라우저 연결 코드로 연결하고 결재 자료 수집을 확인한다. 회사 PC의 코드와 혼동하지 않는다.
10. 오멘에서 보고를 미리 생성해 엑셀·근거·범위 경고를 확인한다. 미리 생성은 이메일을 보내지 않는다. 예약 수집·16:15 생성·본인 발송 스위치를 저장한 뒤 ‘이 PC 예약 등록’을 누른다. 화면 수집 제한을 명시한 보고를 허용할 경우 별도 스위치도 저장한다. 회사 PC는 공유폴더 예약 수집만 켠다.

배포본은 처음 생성한 설정을 반복 실행으로 덮어쓰지 않는다. 기본 데이터 위치는 오멘 `%LOCALAPPDATA%\ARIADNE`, 회사 PC `%LOCALAPPDATA%\ARIADNE-SharedRelay`다. 기존 설치를 이관한 회사 PC는 기존 데이터 경로를 계속 사용할 수 있다. 실행 파일·SQLite DB·암호화 키를 OneDrive에 함께 배치하지 않는다.

기존 설정을 가진 오멘은 새 배포본을 실행해도 자동 덮어쓰지 않는다. 연결 설정에서 웹 방식과 회사 폴더 주소를 직접 저장한다. 이미 회사 OneDrive 앱이 정상 동기화되는 경우에는 선택적으로 ‘OneDrive 앱의 동기화 폴더’를 사용할 수 있다. 이때 각 PC의 로컬 회사 ARIADNE 경로를 지정하고 암호화 파일을 ‘이 장치에 항상 유지’로 설정한다.

## 전달과 복구

OneDrive에는 AES-256-GCM으로 인증 암호화한 `.ariadne-packet` 파일만 전달한다. 메일·Teams·하이웍스·OpenAI 키·Windows 인증 정보는 공유폴더 전달물에 포함하지 않는다. 각 PC의 자료 연결 키는 현재 Windows 사용자 DPAPI로 저장한다.

전달 파일은 발신 PC의 고유 번호와 연속 순번을 사용한다. 파일명도 인증된 본문의 발신 PC·순번과 일치해야 한다. 중간 파일이 누락되거나 다른 회사 PC의 자료가 섞이면 오멘은 이를 거절한다. 파일을 임의로 이름 변경·삭제하지 않는다. 전송 실패 시 회사 PC는 저장된 동일 암호문부터 재전달한다. 이미 받은 자료를 다시 읽어도 DB 버전을 중복 생성하지 않는다. 원본 삭제도 별도 버전으로 남기며 옛 보관본은 유지한다. 원본 파일은 64 MiB, 기본 전달 단위는 512 MiB까지이며 웹 경로의 암호화 전달 파일은 64 MiB까지다.

자료 연결 코드와 회사 발신 DB를 모두 잃으면 새 전달 흐름으로 다시 연결해야 한다. 키를 임의로 바꾸거나 회사 DB를 삭제한 뒤 기존 오멘 DB에 덮어 넣지 않는다. 운영 DB의 일관 백업과 연결 코드 보관은 별도 복구 절차로 관리한다. 배포 파일은 DB·키·과거 메일·캘린더 상태를 자동 이관하지 않는다. 기존 운용 캘린더 자료는 오멘의 일정표 가져오기로 별도 반영해야 한다.

## 실제 운영 확인

회사 공유폴더 보관·회사 웹 업로드·오멘 DB 수신·양쪽 예약 등록이 모두 확인되어야 두 PC 운영이 연결된 상태다. 웹 연결 확인만으로 자료 수신을 완료했다고 판단하지 않는다. 회사 화면의 웹 업로드 시각과 오멘의 원본 확인·수신 시각을 함께 확인한다. 폴더 방식의 ‘전달 폴더 저장 완료’는 로컬 저장 성공이며 클라우드·오멘 도착은 별도 확인한다.

2026-10-01 회사 PC의 실제 18시 예약은 원본 59개를 확인하고 회사 웹 폴더에 순번 3까지 전달·원격 원본 바이트 검증을 완료했다. 오멘 웹 수신은 합성 파일과 독립된 SharePoint 응답 모형으로 검증했다. 오멘 장치에서의 최초 로그인·자료 연결 코드 등록·실제 DB 수신·예약 등록과 첫 금요일 생성·이메일 배달은 현장 확인이 남아 있다.

PC 종료 상태에서는 실행할 수 없다. 예약은 로그인된 현재 사용자만 사용하며 Windows 암호를 저장하지 않는다. 절전 해제를 요청하지만 장치·전원 설정에 따라 실행이 늦거나 빠질 수 있다. 노트북 배터리에서도 예약이 실행 가능하도록 등록한다. Teams는 사용 중이면 생략하고 오후에 다시 화면을 바꾸지 않는다. 최초 실제 금요일 16:15 생성과 Outlook 메일 배달은 별도 확인이 필요하다.

개발자는 `python -m ariadne.desktop --data-dir <로컬 데이터 폴더> --profile <비밀 없는 설정 JSON> omen` 또는 `company-relay`로 같은 실행 경로를 사용한다. 예약은 연결 화면 버튼 또는 `python -m ariadne.desktop --data-dir <데이터 폴더> register`, 중지는 `stop`이다. 연결 상태·역할·예약 등록은 설정 화면에서 관리한다.
