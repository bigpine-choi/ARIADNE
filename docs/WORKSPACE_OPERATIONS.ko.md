# 통합 업무 흐름과 예약 운영

현행 두 PC 운영은 [오멘·회사 PC 안내](HYBRID_OPERATIONS.ko.md)를 우선한다. 오멘에 공유 드라이브 접근이 없으므로 회사 PC는 공유폴더만 수집·전달한다. 각 PC의 DB를 OneDrive에서 함께 열지 않는다. 아래 시간·자료 검증 기준은 유지하며 자동 수집·보고는 각 PC의 역할 설정을 따른다.

ARIADNE는 같은 사이트에서 자료 → 업무 근거 → 운용 일정 → 주간회의 자료를 이어서 사용한다. 자료 저장, 일정 후보, 사용자의 확정, 실제 업무 완료를 별도 상태로 관리한다.

## 실행 일정

| 작업 | 한국시간 | 동작 |
| --- | --- | --- |
| 메일·회의 파일·연결된 하이웍스 문서 수집 | 평일 09~18시 정각 | 1회 수집하고 종료 |
| 지정한 Teams 대화 | 평일 12시 | 하루 1회. Teams를 사용 중이면 생략하고 오후에 재시도하지 않음 |
| 회의 원본의 파일 버전 목록 | 금요일 16시 | 실제 읽은 시각과 원본 해시·버전을 보관 |
| AI 주간회의 자료 생성·본인 메일 발송 | 금요일 16시 15분 | 16시까지의 보고 기간에 해당하는 DB 근거로 생성 |

Windows 작업은 같은 작업의 실행을 Queue로 직렬화한다. 16시 수집이 15분보다 오래 걸리면 그 작업이 종료된 뒤 보고 작업이 시작된다. DB 실행 잠금은 웹 버튼과 예약 작업의 동시 수집도 막는다. 보고 주차 ID와 발송 전 상태 저장은 중복 보고·모호한 발송 재시도를 차단한다.

보고 기간은 연속된 [지난 금요일 16:00, 이번 금요일 16:00)이다. 16:15는 작성 시작 시각이다. 16:15 실행은 hourly collection을 다시 시작하지 않는다. Teams는 금요일 보고 생성 중에 다시 수집하지 않고 낮 12시까지의 보관 자료를 사용한다.

예약 작업은 pythonw.exe를 사용해 콘솔 창을 열지 않는다. UI를 계속 띄워 둘 필요는 없다. PC가 종료되어 있으면 실행하지 못한다. 절전 복귀, 로그인 상태, 공유 드라이브 연결, Outlook 프로필과 회사 정책에 따라 실제 수집 여부가 달라진다. 늦게 읽은 원본을 과거 16시 당시의 원본이라고 표시하지 않는다.

## 한 사이트의 흐름

- 업무 홈: 자료 수집 상태, 다가오는 운용 일정, 업무와 완료 조건.
- 업무 자료: 원본 메일·대화·결재의 최신 보관 버전과 회의 파일 보관본. 열람한 자료를 업무·보고 초안의 근거로 등록.
- 결재 자료: 문서번호·상신 본문·결재선·처리 이력·첨부 이름과 원본 주소. 결재 완료 시각이 있어도 실제 지급·집행 완료로 처리하지 않음.
- 운용 캘린더: 펀드별 정기 일정, 모호한 날짜 확인 목록, 운용 주안점·연락처, AI 일정 후보와 사용자 검토.
- 주간보고: DB를 사용한 미리 생성(발송 없음), 예약 보고 상태, 보관된 엑셀 다운로드와 회사 원본 보관 목록.
- 보관 초안: 기존 기안문 및 보고 초안을 유지. 새로운 기안문 자동 상신은 이번 범위에서 보류.
- 연결 설정: 계정·폴더·채팅 범위·회사 도메인·회사 회의 양식·AI 모델·예약 스위치. OpenAI 키는 기존 DPAPI 저장소를 계속 사용하며 재입력이 필요 없음.

각 기능의 데이터는 같은 데이터 폴더에 있어야 한다. 웹과 예약 작업에 서로 다른 데이터 폴더를 지정하면 별개의 DB가 된다.

## Teams의 입력 간섭과 한계

현재 수집 경로는 Windows UI Automation으로 지정된 대화 선택과 메시지 스크롤을 읽는다. SendInput, 키보드 단축키, 메시지 입력, 클립보드 복사를 사용하지 않는다. 대화와 스크롤은 잠시 바뀔 수 있어 완전한 무간섭 수집이라고 보장하지 않는다.

수집 시작 전과 각 단계에서 Teams가 전면 앱이면 생략·중단한다. 사용자가 Teams를 열었을 때 원래 대화·스크롤을 복원하려고 추가 조작하지 않는다. 지정되지 않은 대화는 DB에 쓰지 않는다. 수집 시 7일을 돌아보되 화면 가상화·접근성 변경·첨부와 누락된 날짜 때문에 전체 이력의 완전성을 보장하지 않는다. 절대 시각과 보관 시각을 구분하며 날짜가 불명확한 내용은 날짜 미확인으로 보존한다.

이전 local_teams.py의 키보드 복사 실험은 이력 참고용으로 남지만 현행 웹·CLI 예약·금요일 보고에서 호출하지 않는다. Microsoft Graph Chat.Read 등의 적절한 권한을 확보하면 화면 이동 없이 읽는 경로로 대체할 수 있다. API 권한은 회사의 Entra 등록·동의 정책을 확인해야 한다.

공식 근거: [채팅 메시지 읽기 API](https://learn.microsoft.com/en-us/graph/api/chat-list-messages?view=graph-rest-1.0).

## 하이웍스 연결

browser-extension/은 로그인된 Chromium 계열 브라우저의 비활성 전용 탭에서 문서함과 문서 열람 DOM만 읽는다. 별도의 비밀번호·쿠키·세션 토큰 추출이 없다. 원본 문서의 첨부 바이트는 내려받지 않으며 이름·원본 URL만 보관한다. 작성·상신·결재·반려 버튼은 누르지 않는다.

내 기안·결재·반려·진행 중 문서함과 부서 문서함을 함께 확인한다. 부서 문서함만 읽으면 진행·반려 문서가 빠질 수 있다. 한 실행은 최대 20페이지·200문서·5분이며 한도를 넘기면 부분 수집으로 표시한다. 확인하지 않은 문서를 먼저, 이후 오래 전에 확인한 문서를 먼저 읽도록 돌아가며 처리한다. 내 문서함의 기본 화면 날짜 필터는 브라우저 원본 범위이며 전체 과거 문서라고 가정하지 않는다.

확장은 아직 설치되지 않은 환경에서는 자동 수집을 할 수 없다. 한 번 확장을 설치하고 연결 설정의 코드를 확장 옵션에 입력해야 한다. 연결 코드는 OpenAI 키와 별개이며 로컬 브리지에만 사용한다.

1. 하이웍스를 쓰는 브라우저의 확장 관리에서 개발자 모드를 켜고 저장소의 browser-extension/ 폴더를 로드한다.
2. ARIADNE 연결 설정에서 브라우저 연결 코드를 확인한다.
3. 확장 옵션에서 코드를 등록한다.
4. ARIADNE 결재 자료에서 수집 버튼을 누르고 실행 기록·보관 버전을 확인한다.
5. 확인 후 하이웍스 포함 스위치를 켠다.

확장 설치는 신규 지속 접근이므로 사용자가 설치·권한을 확인한다. 확장이 접근하는 호스트는 approval.office.hiworks.com과 127.0.0.1:8767뿐이다. 연결 코드·회사 자료·운영 DB는 Git에 넣지 않는다.

## 캘린더

검토한 시트의 업무·메모·연락처만 제한된 스냅샷으로 가져온다. 비밀번호·인증 정보 영역은 가져오지 않는다. 원본 문서 ID·시트·셀 좌표·확인 시각을 보관한다. Google 원본의 시간대와 무관하게 표시된 날짜를 하루 이동시키지 않는다.

말일·마지막 금요일·명시적 날짜 등 확실한 규칙만 계산한다. 영업일, 입금 후, 날짜 충돌·전후 표기는 확인 대기다. 원본 갱신과 AI 재제안은 사용자의 확정 날짜·제목·메모를 덮어쓰지 않는다. 근거가 바뀌면 재검토 표시를 남긴다. AI에는 선택한 일정·운용 메모만 보내고 연락처는 전송하지 않는다. 자동 원본 시트 동기화는 후속이며 현재는 검토한 스냅샷 가져오기이다.

## 회사 회의 엑셀

주간회의 시트의 금주·차주 칸을 분류된 AI 결과로 갱신한다. 원본 양식은 수정하지 않는다. 모든 상세 행·원본 근거·수집 경고를 별도 시트에 붙인다. 보조 시트의 기존 값·수식은 원본 기준 참고자료로 보존하며 이번 주 값으로 갱신되었다고 표시하지 않는다.

과거 회의 자료는 기준일을 표시한 참고자료다. 캘린더 후보는 차주 계획 검토용이며 금주 실적으로 바꾸지 않는다. 현재 보고 기간의 근거가 없고 과거·미래 참고자료만 있으면 생성하지 않는다. 자료가 불완전하면 기본적으로 생성·발송을 차단한다. 제한을 명시한 보고를 허용할 때만 allow_partial_report를 켠다.

## 설치와 예약 등록

Python 3.12 이상, classic Outlook, 로그인된 Teams, Windows Task Scheduler, openpyxl이 필요하다.

~~~powershell
python -m pip install '.[automation]'
python -m ariadne serve --automation-settings C:\LocalConfig\automation.json
.\scripts\register-weekly-task.ps1 -Python C:\Python\python.exe -Project C:\ARIADNE -Settings C:\LocalConfig\automation.json -DataDirectory C:\LocalData\ARIADNE
~~~

연결 설정 저장과 Windows 예약 등록은 별개다. 등록 도구는 기존 ARIADNE Weekly Report 작업을 현행 11개 트리거로 갱신한다. 현재 로그인 사용자, 제한 권한, 한국 시간대와 pythonw.exe가 필요하며 Windows 비밀번호를 저장하지 않는다. 운영 DB·보고 파일·calendar.sqlite3·hiworks.sqlite3·DPAPI 저장소를 소스 저장소 밖에서 별도로 백업한다.

가상 검증은 날짜 규칙·사용자 검토 보존·출처 검증·Teams의 하루 1회/오후 재시도 차단·16:15 보고 분리·동시 실행 차단·원본 버전 보존·엑셀 양식/수식 보존·브리지 출처/코드 검사·중복 발송 방지를 포함한다. 실제 예약 시각 실행과 메일 배달은 코드 테스트와 별도 운영 검증이다.

## AI 분석의 분량과 실패 처리

한 요청의 기본 입력 한도는 240,000자입니다. 한도를 넘는 주간 자료는 최대 8회로 나누어 모든 원천 자료를 분석하며, 근거 ID는 전체 보고서에서 유지합니다. 같은 결과의 중복 행은 근거를 합칩니다. 묶음 사이의 의미 중복은 남을 수 있어 검토가 필요합니다. 단일 자료가 한 요청의 한도를 넘거나 총 8묶음을 넘으면 자료를 조용히 버리지 않고 생성·발송을 중단합니다. 어느 묶음의 분석이 실패해도 부분 결과를 발송하지 않습니다.

과거에 기안된 문서의 이번 주 결재 이력도 보고 근거에 포함합니다. 이번 주 처리 시각이 확인되지 않은 과거 문서는 참고로만 표시합니다. 회사 회의 요약은 한글 줄바꿈을 계산해 상세 시트 안내가 보이도록 제한하고, 상세 내용과 근거는 부록에 보관합니다.

## 구현 모듈과 후속 검증

- workspace.py: 웹·예약 공통 수집, 날짜 범위 선택, 하루 1회 Teams 청구와 실행 잠금. 오래 실행 중인 프로세스의 잠금은 시간 경과만으로 해제하지 않습니다.
- automation_store.py·weekly_archive.py: 원본 바이트와 변경 버전, 금요일 원본 버전 목록.
- teams_uia.py·windows/teams.ps1: 지정 대화만 읽기와 사용 중 중단.
- browser_bridge.py·browser-extension/: 승인한 확장과 로컬 수집 요청, 비활성 탭의 문서·결재 이력 읽기.
- calendar.py·calendar_ai.py: 출처가 있는 일정·메모·연락처와 검토된 AI 일정 후보.
- reporting.py·meeting_report.py·weekly_worker.py: DB 근거 분석, 회사 양식 보존, 발송 접수와 결과 불명 상태 보호.

후속 항목은 Graph 수집 권한 연결, Google 원본 자동 동기화, Teams 전체 기간 보장, 하이웍스 한도와 화면 변경 운영 확인, 실제 금요일 실행·이메일 도착 확인입니다. 가상 테스트 142개는 날짜·근거·중복·출처·양식·발송 경계를 검증합니다.

## 확장 설치에서 파일 선택 수 안내가 뜰 때

압축해제된 확장 폴더 선택에서 WaterWall 제목의 “첨부파일은 한개씩 선택하여 주세요”가 뜨면 설치 성공으로 처리하지 않습니다. 폴더 읽기를 파일 첨부로 검사한 가능성이 있으나 정확한 정책은 회사 보안 담당자의 로그로 확인해야 합니다. 안내 문구만으로 확장 설치 금지를 단정하지 않습니다. 보안 프로그램 중지, 정책 우회, 다른 경로의 강제 설치는 사용하지 않습니다. Whale의 확장앱 압축은 단일 `.whx` 파일과 업데이트 서명용 `.pem` 키 파일을 생성합니다. 설치에는 압축해제된 확장앱 설치 버튼을 누르지 않고 탐색기의 `.whx` 하나를 확장 관리 페이지의 빈 공간으로 끌어다 놓습니다. `.pem`은 공유하거나 Git에 올리지 않습니다. 원래 생성된 파일 중 설치에는 `.whx` 하나만 사용하고 `.pem`은 공유하거나 Git에 올리지 않습니다. Chromium에서 압축한 경우에는 `.crx`가 생성됩니다. 실제 설치·브리지 응답을 확인할 때까지 하이웍스 자동 수집 스위치는 끈 상태로 유지합니다. 추가 차단 안내가 있다면 회사가 승인한 설치·연동 경로를 확인합니다. 기존 보관 문서는 읽을 수 있습니다.

브리지는 `whale-extension://` 및 `chrome-extension://` 뒤에 32자리 `[a-p]` 확장 ID가 붙은 출처만 허용합니다. 두 브라우저 모두 발급된 연결 코드와 정확한 로컬 Host가 필요하며, 일반 웹 페이지는 수집 큐를 조회하거나 DB에 자료를 쓸 수 없습니다. Whale 주소 형식과 API 호환성은 [Whale 공식 개발 문서](https://developers.whale.naver.com/getting_started/anatomy_1/) 및 [브라우저 API](https://developers.whale.naver.com/api/)를 따릅니다. 개발자 모드 설치 확장은 브라우저 재시작 때 재확인 또는 비활성화될 수 있으므로, 무인 운용 전에 재시작 후 연결도 검증해야 합니다.
