## 현재 체크포인트와 다음 개발 묶음

1. B01의 기초 코드 검토를 완료했고 B02~B03의 기존 모델·SQLite·감사·확정값 보호를 재사용했다. 재실행·가상 백업/복원 테스트 통과와 전체 마이그레이션·운영 복구 검증은 구분한다. B38의 계약 통합 과제는 남아 있다.
2. B04는 로컬 웹 목록·상세·근거·이력·수정·수기 등록·제안 검토를 구현했다. 완료 차단·두 창의 충돌·입력 보존·서버 재시작 등 브라우저 10개 흐름의 CI 인수를 확인한다.
3. B39는 Windows 자격증명 보관을 구현했다. 네이티브 저장·재조회·삭제 CI를 확인한다. 저장 상태 표시는 OpenAI 인증 성공 표시가 아니며 실제 공급자 호출은 없다.
4. B05~B06의 MSG 가져오기·정규화를 다음으로 구현한다. 합성 자료로 원본 보존·해시·중복·실패·본문/첨부 범위 기록을 검증한 뒤 허용된 실제 자료로 평가한다.
5. B23은 `CredentialService.get_openai_key()`로 서버에서 키를 읽고 추출을 실행하도록 연결한다. B07~B10·B25~B27·B33~B34와 함께 비용·실패·근거 검증, 업무 제안과 사용자 확정·보존 흐름을 완성한다.
6. B24는 권한 확보 시 병행한다. v0.3의 OAuth 갱신은 가능한 범위에서 자동 처리하되 철회·만료·정책 변경으로 재인증이 필요한 경우 안내한다. 연결 성공을 MSG·웹 개발의 선행조건으로 두지 않는다.

B28~B30은 B10 이후 가상 자료로 먼저 시제품을 만들 수 있다. 실제 개인 운용 출시는 v0.4·v0.5의 계산·근거·검토 기반을 충족해야 하며, 팀 공유에는 v0.6 권한·운영 조건도 필요하다.

## 인수·검증 원칙

- 메일 목록 385개는 이번 점검의 가용 재고다. 고정 테스트 건수로 하드코딩하지 않고 매 가져오기에서 성공·실패·중복·미지원 건수를 대사한다.
- 초기 백서의 523개/ZIP 5개는 과거 점검 기록이며 이번 ZIP 4개와 다르다. 미전달 자료를 분석했다고 표시하지 않는다.
- 과거 분석시각을 기준으로 평가한다. 미래 회신을 이전 시점의 판단에 섞거나 같은 거래를 조정용·평가용으로 나누지 않는다.
- 근거 없는 확정·완료, 사용자 확정값 덮어쓰기, 재시도로 발생한 중복 변경, 권한 밖 노출은 출시용 검증셋에서 0건을 게이트로 삼는다. 실제 운영의 무오류 보장이 아니다.
- 중요한 요청 누락률·오탐·병합 오류·날짜 정확도·보류율은 분모와 함께 보고하고, 자동 반영 기준은 업무자가 승인한 평가 결과로 정한다.
- 템플릿 출력은 계산 결과와 기존 양식의 수식·스타일·숨김·인쇄 상태를 검증한다. 검증용 셀·메모를 업무 산출물에 임의 추가하지 않는다.
- 실제 메일·문서·금액·계좌·개인정보는 Git 테스트 자료로 사용하지 않는다. 가상 또는 승인된 비식별 사례를 사용한다.
- 단계 완료 시 목적·기능·데이터 구조·실행 방법·검증 결과·한계·다음 과제를 기록한다. 계획·코드 존재·실행 통과·실계정 검증을 구분한다.

## 운영 범위

개인 파일럿은 단일 사용자의 승인된 실행 환경에서 운영한다. PC 종료 중 24시간 처리는 승인된 상시 서버가 있어야 가능하다. 팀·외부 공개 배포는 v0.6 조건을 충족한 뒤 수행한다. 외부 발송·일정 변경·운용지시 제출·자금집행은 이 계획 커밋과 별개의 실행 승인 대상이며, 원본 삭제는 초기 기능 범위에 없다.
