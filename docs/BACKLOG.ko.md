# ARIADNE 개발 백로그

기준일: 2026-10-01, Asia/Seoul
현행 기준: [개발 계획](DEVELOPMENT_PLAN.ko.md), [코드 구조·연동 설계](ARCHITECTURE.ko.md).

현재 구현은 `feature/local-outlook-collect-v0.2.2`의 **클래식 Outlook 지금 수집**이다. 기존 B11·B06·B25 기초에 폴더 선택·제한 수집·진행 결과·로컬 원천 보존을 추가했다. 기본 COM 접근은 사용자 PC에서 확인했으며 앱 버튼의 실메일 저장 인수·페이지 이어받기·주기적 수집·AI는 남아 있다. [범위와 검증](LOCAL_OUTLOOK.ko.md)을 참고한다. MSG·EML 가져오기는 계속 보류하며 기존 B01~B39 ID를 유지한다.

[feature/week1-foundation의 고정 기준](https://github.com/bigpine-choi/ARIADNE/tree/14f47c8ab02a60cb266837041ab0b797f4adb719)의 기초 구현을 검토·재사용했습니다. 기초 코드 변경 전 테스트 42개가 통과했고 v0.1.1 당시 Linux Python 테스트는 **65개 중 64개 통과, Windows 전용 1개 건너뜀**입니다. GitHub CI에서는 Windows의 65개 전체 테스트, Linux 회귀, Chromium 10개 흐름, Godot 엔진 검증을 통과했습니다. [실행 결과](https://github.com/bigpine-choi/ARIADNE/actions/runs/36756761270)는 코드 `162d7152f5982061f0167941fecd75ef58cb1720` 기준입니다. 이는 v0.1.1의 이력입니다. v0.2.0 검증은 [Outlook 연결 안내](OUTLOOK_CONNECTION.ko.md), v0.2.1 검증은 [메일 근거함 안내](MAIL_EVIDENCE.ko.md)에 별도로 기록합니다. 단계 전체 완료·운영 복구·실제 AI·회사 Outlook 연결이 검증된 것으로 해석하지 않습니다.

## 현재 체크포인트와 다음 개발 묶음

1. B01의 기초 코드 검토를 완료했고 B02~B03의 기존 모델·SQLite·감사·확정값 보호를 재사용했다. 재실행·가상 백업/복원 테스트 통과와 전체 마이그레이션·운영 복구 검증은 구분한다. B38의 계약 통합 과제는 남아 있다.
2. B04는 로컬 웹 목록·상세·근거·이력·수정·수기 등록·제안 검토를 구현했다. 완료 차단·두 창의 충돌·입력 보존·서버 재시작 등 브라우저 10개 흐름의 CI 인수를 통과했다. 사용자 PC의 한글 IME·사용성 확인은 남아 있다.
3. B39는 Windows 자격증명 보관을 구현했다. 네이티브 저장·재조회·교체·삭제 CI를 통과했다. 저장 상태 표시는 OpenAI 인증 성공 표시가 아니며 실제 공급자 호출은 없다.
4. B11의 연결·인증 재사용·미리보기에 B06·B25 기초를 추가했다. 최대 10건 선택 저장, 본문·첨부 목록 보존, 계정별 중복·변경 버전, 근거함·업무 연결이 가능하다. 스키마 전환은 기존 사용자 확정값·이력을 보존한다. 회사 계정 인수·첨부 내용 파서·delta는 남아 있으며 저장한 메일은 연결 해제 시 삭제되지 않는다.
5. 이후 B23은 `CredentialService.get_openai_key()`로 서버에서 키를 읽고 허용된 정규화 메일의 추출을 실행하도록 연결한다. B07~B10·B25~B27·B33~B34와 함께 비용·실패·근거 검증, 업무 제안과 사용자 확정·보존 흐름을 완성한다.
6. B12~B13은 v0.3에서 지속적 delta 수집·체크포인트·중단 복구로 확장한다. B24의 MCP 커넥터는 필요성이 있을 때 별도로 검증한다. B05의 MSG/EML·메일 ZIP 가져오기는 보류하며 초기 출시의 필수 기능으로 두지 않는다. 계정 연결이 막히면 권한 문제를 안내하고 합성 응답으로 개발을 계속하며, 사용자 요청 없이 파일 가져오기를 대신 구현하지 않는다.

B28~B30은 B10 이후 가상 자료로 먼저 시제품을 만들 수 있다. 실제 개인 운용 출시는 v0.4·v0.5의 계산·근거·검토 기반을 충족해야 하며, 팀 공유에는 v0.6 권한·운영 조건도 필요하다.

## 인수·검증 원칙

- 메일 목록 385개는 과거 파일 자료의 가용 재고 기록이며 Outlook 인수의 필수 입력이나 고정 테스트 건수가 아니다. Graph 수집은 지정한 기간·폴더·건수와 실제 성공·실패·중복·미수집 범위를 대사한다.
- 초기 백서의 523개/ZIP 5개는 과거 점검 기록이며 이번 ZIP 4개와 다르다. 미전달 자료를 분석했다고 표시하지 않는다.
- 과거 분석시각을 기준으로 평가한다. 미래 회신을 이전 시점의 판단에 섞거나 같은 거래를 조정용·평가용으로 나누지 않는다.
- 근거 없는 확정·완료, 사용자 확정값 덮어쓰기, 재시도로 발생한 중복 변경, 권한 밖 노출은 출시용 검증셋에서 0건을 게이트로 삼는다. 실제 운영의 무오류 보장이 아니다.
- 중요한 요청 누락률·오탐·병합 오류·날짜 정확도·보류율은 분모와 함께 보고하고, 자동 반영 기준은 업무자가 승인한 평가 결과로 정한다.
- 템플릿 출력은 계산 결과와 기존 양식의 수식·스타일·숨김·인쇄 상태를 검증한다. 검증용 셀·메모를 업무 산출물에 임의 추가하지 않는다.
- 실제 메일·문서·금액·계좌·개인정보는 Git 테스트 자료로 사용하지 않는다. 가상 또는 승인된 비식별 사례를 사용한다.
- 단계 완료 시 목적·기능·데이터 구조·실행 방법·검증 결과·한계·다음 과제를 기록한다. 계획·코드 존재·실행 통과·실계정 검증을 구분한다.

## 운영 범위

개인 파일럿은 단일 사용자의 승인된 실행 환경에서 운영한다. PC 종료 중 24시간 처리는 승인된 상시 서버가 있어야 가능하다. 팀·외부 공개 배포는 v0.6 조건을 충족한 뒤 수행한다. 외부 발송·일정 변경·운용지시 제출·자금집행은 이 계획 커밋과 별개의 실행 승인 대상이며, 원본 삭제는 초기 기능 범위에 없다.
