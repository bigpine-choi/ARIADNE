# ARIADNE 개발 백로그

> 2026-10-01 현행 개정: 통합 자료·캘린더·상신/결재 보관·회사 회의 엑셀·평일 매시간 수집, Teams 평일 12시 1회, 금요일 보고 생성 16:15 및 순차 실행은 [통합 업무와 예약 운영](WORKSPACE_OPERATIONS.ko.md)을 따른다. 아래 이전 키보드 복사·5분 예약·16시 생성 설명은 초기 구현 이력이며 현행 예약 경로가 아니다. 기안문 자동 상신은 보류한다.


기준일: 2026-10-01, Asia/Seoul
현행 기준: [개발 계획](DEVELOPMENT_PLAN.ko.md), [코드 구조·연동 설계](ARCHITECTURE.ko.md).

기존 B01~B38 ID를 유지하고 현재 구현·검증 상태를 갱신했습니다. B39~B42는 로컬 파일·메일·Teams·주간보고 운영을 위한 작업입니다. B43~B48은 이번 하이웍스 초안·키 등록·공식 연동·운영 검증 작업입니다. ID 순서가 실행 순서를 뜻하지 않습니다. 부분 구현은 해당 행의 전체 완료조건을 충족했다는 뜻이 아닙니다.

[foundation 고정 기준](https://github.com/bigpine-choi/ARIADNE/tree/14f47c8ab02a60cb266837041ab0b797f4adb719)의 Python을 선별 통합했고, 기존 42개·신규 28개 테스트와 네 환경의 CI가 통과했습니다. 파일 59개·메일 110건의 제한된 실수집을 검증했습니다. 현재 코드와 운영 한계는 [로컬 자동화 안내](LOCAL_AUTOMATION.ko.md)를 따릅니다. Teams 전체 주간 이력·AI 품질·실메일 배달·예약 운영은 남아 있습니다.

## 인수·검증 원칙

- 현재 파일 59개·메일 110건은 개발 당일 제한된 수집 검증이다. 이전 MSG 385개는 당시의 목록 집계다. 고정 테스트 건수로 하드코딩하거나 수치를 합산하지 않고 매 수집에서 성공·실패·중복·미지원 범위를 대사한다.
- 초기 백서의 523개/ZIP 5개는 과거 점검 기록이며 이번 ZIP 4개와 다르다. 미전달 자료를 분석했다고 표시하지 않는다.
- 과거 분석시각을 기준으로 평가한다. 미래 회신을 이전 시점의 판단에 섞거나 같은 거래를 조정용·평가용으로 나누지 않는다.
- 근거 없는 확정·완료, 사용자 확정값 덮어쓰기, 재시도로 발생한 중복 변경, 권한 밖 노출은 출시용 검증셋에서 0건을 게이트로 삼는다. 실제 운영의 무오류 보장이 아니다.
- 중요한 요청 누락률·오탐·병합 오류·날짜 정확도·보류율은 분모와 함께 보고하고, 자동 반영 기준은 업무자가 승인한 평가 결과로 정한다.
- 템플릿 출력은 계산 결과와 기존 양식의 수식·스타일·숨김·인쇄 상태를 검증한다. 검증용 셀·메모를 업무 산출물에 임의 추가하지 않는다.
- 실제 메일·문서·금액·계좌·개인정보는 Git 테스트 자료로 사용하지 않는다. 가상 또는 승인된 비식별 사례를 사용한다.
- 단계 완료 시 목적·기능·데이터 구조·실행 방법·검증 결과·한계·다음 과제를 기록한다. 계획·코드 존재·실행 통과·실계정 검증을 구분한다.

## 운영 범위

개인 파일럿은 단일 사용자의 실행 환경에서 운영한다. 현재 본인 주간보고 코드는 기본 비활성이며 B42 검증 후 명시적 설정으로 활성화한다. PC 종료 중 처리는 수행하지 않는다. 팀·외부 공개 배포는 v0.6 조건을 충족한 뒤 수행한다. 임의 수신자 발송·일정 변경·운용지시 제출·자금집행은 별도 승인·권한 기능의 대상이며, 원본 삭제 기능은 없다.
