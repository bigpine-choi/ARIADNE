# 하이웍스 기안문·주간업무보고 자동화

> 2026-10-01 현행 개정: 통합 자료·캘린더·상신/결재 보관·회사 회의 엑셀·평일 매시간 수집, Teams 평일 12시 1회, 금요일 보고 생성 16:15 및 순차 실행은 [통합 업무와 예약 운영](WORKSPACE_OPERATIONS.ko.md)을 따른다. 아래 이전 키보드 복사·5분 예약·16시 생성 설명은 초기 구현 이력이며 현행 예약 경로가 아니다. 기안문 자동 상신은 보류한다.


기준일: 2026-10-01, Asia/Seoul. 실제 화면 관찰, 공식 API 명세, 구현·검증, 후속 계획을 구분한다. 회사 문서 원문·계좌·인명·첨부·로그인 세션은 저장소에 복제하지 않았다.

## 1. 회사 화면 분석

사용자가 제공한 문서 열람 화면과 작성하기 → 품의서, 결재선 설정 대화상자를 확인했다. 테스트 문서를 회사에 저장하거나 상신하지 않았다.

| 확인한 화면 | 관찰한 구조 | 개발에 적용 |
| --- | --- | --- |
| 문서 열람 | 기안 부서·기안자·문서번호·보존 연한·보안 등급·문서함 | 초안의 업무 본문과 하이웍스 메타데이터를 분리 |
| 문서 열람 | 결재·합의·참조, 처리 표시, 의견·이력 | 승인 완료를 단순 본문·발송 여부로 판정하지 않음 |

| 품의서 선택 | 보존 5년·A등급과 기본 결재선이 표시됨 | UI 기본값에 반영하되 업무별 확인 필요 |
| 기본 설정 | 보존 1·3·5·10년·영구, 보안 S·A·B·C, 문서함 | 값 검증; 조회 문서의 메타데이터를 무조건 복사하지 않음 |
| 결재선 설정 | 결재·합의·재무합의·참조, 사용자 검색, 자주 쓰는 결재선 | 코드 계약에 역할 구분; 실제 결재선 지정은 후속 |
| 본문·별첨 | 제목 입력, iframe 기반 리치텍스트 편집기, 파일·관련문서 첨부 | HTML/텍스트 복사·다운로드, 첨부 예정 목록 표시 |
| 문서함 | 진행·기안·반려·임시저장 등 | 로컬 초안 보관과 회사 임시저장을 구분 |

확인한 DOM 단서는 제목의 `approval_document_title`, 결재선 버튼의 `btnApprovalAdressbookSelect`, 첨부의 `fileApprovalAttach`, 보존·보안 선택자의 `set_preserved_term_y`·`set_security_level_y`다. 작성 양식 선택자는 `select[name="approval_form_no"]`다. 편집기 iframe에는 범용적으로 신뢰할 식별자를 확인하지 못했다. 미래 UI 어댑터는 양식·프레임·편집 가능 상태를 재관찰한 뒤 입력과 읽기 검증을 해야 한다. 지금 코드에서 화면 자동 입력·회사 임시저장·상신을 구현했다고 표시하지 않는다.

주간보고 전용 양식은 확인한 공통 목록에 없었다. 보고가 업무연락·회람·메일·회의록 중 어느 경로인지 아직 미확정이다. 기존 개인 XLSX 보고 경로와 같은 보고 데이터로 HTML 초안을 만드는 방식으로 착수했다. 기존 회사 회의록의 여러 시트·수식 보존 기능은 이번 구현 범위가 아니다.

## 2. 공식 연동 방식과 결정

[하이웍스 개발자센터](https://developers.hiworks.com/docs)에서 연결한 [공식 API 명세](https://documenter.getpostman.com/view/6863253/S1TVWcri?version=latest)를 확인했다.

전자결재 기안은 `POST https://api.hiworks.com/office/approval/documents`로 준비한 내용을 전달하고 응답의 `login_url` 기안 페이지를 사용자에게 보여주는 방식이다. 로그인·결재선·첨부·상신은 별도 절차다. 문서 상태 조회는 `GET https://api.hiworks.com/approval/v2/documents/{문서번호}`다. 문서 열람에서 보인 회사 내부 API는 공식 외부 API와 구분하며 사용하지 않는다.

API 요청은 `form_id`, 제목 `subject`, 본문 `contents`, `callback_url`, 본문·파일 수정 허용 플래그를 사용한다. 공식 API용 양식 ID는 관리자 설정으로 발급하는 값이다. UI의 숫자 양식 번호를 API용 ID로 가정하지 않는다. Office Token은 서버의 별도 비밀정보로 관리해야 한다. 신규 OAuth Access Token 발급은 명세상 중단된 상태다.

콜백은 GET으로 도착하며 명세상 `state`가 문서 상태이고 요청 시 넣은 상관값은 `request_hash`에 반환된다. 이 이름 차이를 계약 테스트로 확인해야 한다. 인증이 확인되지 않은 콜백만으로 업무 완료를 바꾸지 않고 공식 상태 조회와 대사한다. 상태는 progress·rejected·canceled·complete·deleted를 원천 상태로 보존하고 자금집행 완료와 분리한다.

현재 `build_page_link_payload`는 명세에 맞는 요청 본문만 만든다. 네트워크·토큰·콜백 수신기·상태 변경은 없다. 파일 인코딩 검증 전 첨부 예정 목록이 있는 요청은 생성 차단한다. 메타데이터·결재선은 API 본문에 임의 필드를 추가하지 않고 실제 연동 양식에서 확인할 계획이다.

결정: **로컬 초안 생성 → 공식 기안 페이지 연동 → 검증된 상태 대사** 순서다. 공식 API 권한이 없으면 현재 복사·HTML 다운로드로 업무를 이어간다. 하이웍스 화면 자동 입력은 공식 API와 양식 권한 검토 후 대안으로 다룬다.

## 3. 현재 구현

- `ariadne/hiworks.py`: 품의서 구조화 입력·Decimal 원 단위 합계 대사·날짜·근거·메타데이터 검사, HTML 이스케이프, 주간보고 HTML/텍스트, 공식 API 본문 생성.
- `DraftStore`: `hiworks.sqlite3`에 초안과 내용 식별 해시를 보관한다. 같은 내용은 중복 생성하지 않으며 바뀐 내용은 새 초안이 된다. 기존 초안은 유지한다.
- `weekly_worker.py`: 기존 근거 검증 보고 데이터에서 XLSX와 하이웍스용 초안을 함께 생성한다. prepared 실행 정보에 초안 ID를 남긴다. 실제 하이웍스에는 보내지 않는다.
- 웹: 최초 키 등록, 품의서 입력, 저장된 근거 선택, 금액 불일치 안내, 초안 목록·재열람·미리보기·제목/HTML 본문 복사·HTML 다운로드.
- 웹 입력은 청구 항목 1개를 지원하며 Python/HTTP 계약은 여러 항목을 지원한다. 결재선 입력 UI, 실제 파일 업로드, 기존 회사 보고 양식 편집, 기안문 AI 문장 다듬기는 후속이다.
- HTTP 기안 생성 시 근거 ID는 기존 업무 DB에 등록된 값만 허용한다. 본문·첨부 목록의 근거도 기안의 근거 집합에 속해야 한다. 이 검사는 근거 존재·연결 검사이며 원문 금액·계좌 사실의 자동 검증은 아니다.

| HTTP 경로 | 역할 |
| --- | --- |
| GET /api/hiworks/drafts | 최근 100개 초안 목록 |
| POST /api/hiworks/drafts | 검증된 품의서 초안 생성·로컬 보관 |
| GET /api/hiworks/drafts/{해시} | 초안 재열람 |
| GET /api/settings/openai | 키 등록 여부·지원 여부; 키 반환 없음 |
| POST /api/settings/openai | 사용자가 입력한 키 암호화 저장·교체 |
| POST /api/settings/openai/remove | 저장된 로컬 키 삭제; 공급자 키 폐기 아님 |

구조화 요청 예제는 [가상 품의서 JSON](../examples/hiworks-approval.json)이며 데모에 등록된 가상 근거를 사용한다.

기존 루프백·Host/Origin·JSON 용량 제한을 유지한다. 자동화 설정 없이도 초안 작성과 키 등록 화면은 작동한다. 업무 상태를 기안 생성으로 완료 처리하지 않는다.

## 4. OpenAI 키 최초 1회 등록

[OpenAI 인증 안내](https://developers.openai.com/api/reference/overview)에 따라 키는 서버에서 읽고 API 요청 헤더에만 사용한다. 최초 등록 시 로컬 웹의 비밀번호 입력란에 **사용자가 직접** 넣는다. 브라우저에 다시 반환하거나 localStorage·설정 JSON·Git·로그에 남기지 않는다. 입력란은 요청 후 비운다.

Windows DPAPI의 현재 사용자 암호화를 사용한다. `%LOCALAPPDATA%\\ARIADNE\\credentials\\openai.dpapi`에 암호문만 저장하고 원자적으로 교체한다. `ARIADNE_DATA_DIR`를 지정하면 그 위치의 `credentials/`를 사용한다. 웹·주간 작업자·예약 작업은 같은 Windows 계정과 데이터 위치를 사용해야 한다. 저장 키를 우선 사용하고 미등록일 때만 기존 `OPENAI_API_KEY` 환경변수를 사용한다. 재시작·다음 주 실행마다 입력하지 않는다.

키 저장은 유효성·모델 권한·결제 한도 확인이 아니다. 삭제·교체 버튼을 제공하며 폐기·만료·권한 변경 시 재등록이 필요하다. 손상된 저장 키를 환경변수로 조용히 대체하지 않는다. Windows 외에서는 환경변수 경로를 유지하며 평문 영구 저장으로 대체하지 않는다. 같은 계정의 악성 프로그램이나 관리자에 대한 격리는 DPAPI만으로 보장되지 않는다.

근거: [Microsoft CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata). 실제 API 키 등록이나 외부 OpenAI 호출은 이번 개발 검증에 포함하지 않았다.

## 5. 실행

```powershell
python -m pip install '.[automation]'
python -m ariadne serve --demo
```

`http://127.0.0.1:8765/`에서 가상 근거를 선택해 품의서를 작성한다. 실제 사용에는 등록된 실제 근거와 확정된 입력을 사용한다. 초안·계좌가 들어간 DB와 키 암호문은 저장소 밖에 보관한다. 기본 실행에서는 회사 로그인·AI 호출·상신이 발생하지 않는다.

기존 자동 보고는 [로컬 자동화 안내](LOCAL_AUTOMATION.ko.md)의 계정·모델·수집 범위·스위치를 그대로 사용한다. `weekly`가 생성한 초안은 같은 데이터 위치를 사용하는 웹의 초안 목록에서 확인한다. 기존 업무 백업 명령은 `hiworks.sqlite3`를 포함하지 않으므로 별도 SQLite 일관 백업 대상으로 추가한다. 키 암호문을 다른 계정이나 PC에 복사해 복구할 수 있다고 가정하지 않는다.

## 6. 후속 개발 계획과 완료조건

| 단계 / 백로그 | 작업 | 선행조건·완료조건 |
| --- | --- | --- |
| H1 / B43 | 회사 화면·API 분석 | 화면 관찰과 명세·미확정 항목 기록 완료 |
| H2 / B44 | 초안·금액·근거·보관·웹 | 현재 MVP 구현; 다중 청구 UI·원문 대사·빈 양식 검증 후 실사용 확대 |
| H3 / B45 | 최초 1회 키 등록 | 암호문 보관·새 프로세스 재사용·교체·삭제·오류 비노출 테스트 완료; 실제 키 연결은 별도 |
| H4 / B46 | 공식 기안 페이지 연결 | 회사 관리자 제공 API용 form_id·최소 Office Token·승인된 콜백 주소, 테스트 문서 사용 범위 확정; 첨부 인코딩·응답 URL 검증·결재선 대사 |
| H5 / B47 | 상태 수집·콜백 대사 | H4, 상관 ID·원천 문서 ID·상태 조회·중복 이벤트·위조·역순·반려/취소 사례. 결과 불명일 때 재상신 금지 |
| H6 / B48 | 실제 주간보고 운영 | 제출 양식·수신 경로·기간·담당자 확정, 실제 보고 정답 대조, 누락 표시·수정 보존·예약 재개 검증 |

B46 실행에서는 API 기안 화면을 준비하기 전 정확한 제목·본문·첨부·목적지를 검토하고, 최종 상신은 사용자 단계로 둔다. 이후 상신 자동화를 요청받으면 실행 직전 승인·본문/첨부 해시·리비전·세션·중복·결과 대사부터 구현한다. 현재에는 이런 실행기나 승인 큐가 없다.

## 7. 검증 범위

Windows 가상 자료 테스트는 금액 대사, 잘못된 날짜·근거·첨부 경로, HTML 실행문 차단, 초안 중복·재시작 보존, 보고 기간 종료 경계, HTTP 출처 검사, DPAPI 암호문·교체·삭제·새 프로세스 읽기, 저장 키로 보고 API 요청 구성까지 검사한다. OpenAI 요청은 가상 응답으로 대체한다.

브라우저에서 가상 품의서의 잘못된 총액이 차단되고 정상 총액은 표·미리보기와 함께 저장되는 것을 확인했다. 실제 Windows 사용자 암호화 검증은 제한된 샌드박스가 아닌 사용자 실행 환경에서 가상 키로 수행했다. 테스트 결과의 최신 수치는 [변경 기록](../CHANGELOG.md)을 따른다.

실제 Office Token·외부 form_id·OpenAI 키·회사 첨부 인코딩·하이웍스 임시저장/상신·상태 콜백·실보고 배달·예약 운영은 미검증이다. 이 한계를 MVP와 후속 출시 기준에 유지한다.
