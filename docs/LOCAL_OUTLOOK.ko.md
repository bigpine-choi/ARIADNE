# v0.2.2 · 이 PC의 Outlook에서 지금 수집

기준일: 2026-10-01, Asia/Seoul. 브랜치: `feature/local-outlook-collect-v0.2.2`.

## 준비와 실행

Windows의 **클래식 Outlook**에 회사 계정으로 로그인하고 ARIADNE를 같은 Windows 사용자로 실행한다. 이 수집 경로에는 Microsoft 앱 ID·시크릿, Graph 권한, MCP·플러그인, OpenAI 키가 필요하지 않다. 새 Outlook·웹 Outlook·Windows 서비스 실행용 수집기는 아니다. 회사의 프로그램 접근 제한과 Outlook 보안 확인을 그대로 따르며 보안 설정을 바꾸지 않는다.

Python 3.12 이상이 설치된 PC에서 위 브랜치의 저장소 폴더를 연다. 기존 저장소라면 변경 사항을 보관한 뒤 해당 브랜치로 전환한다. 새 설치는 GitHub에서 해당 브랜치의 ZIP을 다운로드하여 압축을 풀어도 된다.

```powershell
python -m pip install -e .
python -m ariadne serve
```

브라우저에서 <http://127.0.0.1:8765>를 연다. 이 주소는 ARIADNE를 실행한 같은 PC에서 연다. 앞서 제공한 HTML 미리보기 파일은 실행 앱이 아니므로 수집할 수 없다. Graph 연결도 사용할 경우에만 `python -m pip install -e ".[outlook]"`가 추가로 필요하다.

기존 DB를 사용한다면 업데이트 전에 이전 앱의 `backup` 명령으로 백업한다. v0.2.1의 schema 2는 유지하며, schema 1 DB에는 기존 1→2 전환이 적용된다. 이전에 `--db`로 별도 DB를 지정했다면 같은 경로로 실행해야 기존 업무가 보인다.

## 사용 순서

1. 화면 오른쪽 위 **지금 수집**을 누른다.
2. **사서함·폴더 불러오기**를 누른다. 실제 Outlook에서 접근할 수 있는 메일 폴더를 확인한다.
3. 사서함과 폴더 하나를 선택한다. 받은 편지함 아래 펀드별 하위 폴더도 목록에서 각각 선택할 수 있다. 부모 폴더 선택만으로 하위 폴더를 일괄 수집하지 않는다.
4. 조회 기준을 정한다. 받은 메일은 **수신 시각**, 보낸 편지함은 **발신 시각**을 선택한다. 폴더 이름으로 수신·발신을 추측하지 않는다.
5. 한국시간 시작일·종료일, 최대 건수, 수집자 이름을 입력한다. 기본은 최근 7일·10건이며 종료일을 포함한다.
6. **지금 수집**을 누른다. 읽는 중에는 결과를 기다리고, 완료 후 신규·기존과 동일·변경 버전·실패 건수를 확인한다.
7. **메일 근거함 열기**에서 본문·첨부 목록·원천 폴더를 확인하고 기존 업무에 연결한다.

창을 닫아도 서버가 실행 중이면 수집은 계속된다. 다시 열거나 **진행 상태 확인**을 눌러 현재 작업과 최근 결과를 확인한다. 수집창의 상태가 갱신되지 않을 때 반복 실행 전에 이 버튼으로 확인한다. 읽기 시간은 최대 180초이며 Outlook 접근 확인 창 등으로 지연되면 실패로 표시한다. ARIADNE가 Outlook 자체를 종료하지는 않는다.

## 범위와 부분 결과

- 1회 **폴더 1개·최대 31일·1~50건**, 최신 메일부터 읽는다. 메일 외 항목은 제외한다.
- 폴더 탐색은 최대 50개 저장소·2,000개 폴더 방문·16단계 깊이이며 접근 실패·상한 도달을 표시한다.
- 본문은 최대 100,000자, 수신자 조회는 최대 100명, 첨부 목록은 최대 100개로 제한한다. 잘린 항목은 기존 근거함에서 일부 보관으로 표시한다. 받는 사람(To) 목록을 보관하며 참조·숨은 참조 전체 기록 기능은 아니다.
- 첨부 이름·형식·크기·본문 포함 여부 등 **메타데이터만** 읽는다. 첨부 다운로드·PDF/Excel 분석·외부 이미지 로드는 하지 않는다.
- 한 건의 본문이나 첨부 목록을 읽다가 오류가 나거나 읽는 도중 메일이 변경되면 그 메일은 실패 건수로 처리한다. 다른 성공 메일은 저장한다. 저장은 메일별 트랜잭션이며 Graph의 최대 10건 전체 원자 저장과 구분한다.
- 더 읽을 메일이 있으면 **일부 수집**을 표시한다. 기간을 나누어 확인할 수 있지만, **하루에 50건을 넘는 폴더의 나머지 페이지를 이어 읽는 기능은 아직 없다.** 같은 조건을 반복해도 최신 상한 건수를 다시 확인하므로 전체 수집 완료로 취급하지 않는다.
- 작업 목록·폴더 선택 권한은 서버 메모리에만 보관한다. 폴더 목록은 30분 뒤 다시 조회해야 한다. 서버 재시작 시 진행 작업은 자동 재개하지 않는다. 이미 저장된 메일은 남으며, 다시 폴더를 선택해 같은 범위를 수집하면 같은 내용은 중복 저장하지 않는다.

메일 읽음 상태·메일 내용·원본 폴더를 쓰는 동작과 발송·삭제·이동은 없다. 새 메일이 서버에 있으나 Outlook에 아직 동기화되지 않은 경우나 접근이 제한된 폴더까지 모두 수집됐다고 보장하지 않는다. 주기적 수집·누락 복구·다중 PC 동시 작업은 후속 범위다.

## 보관과 식별

기존 메일 근거함과 같은 SQLite DB에 본문·주소·첨부 목록을 **암호화하지 않은 형태로 저장**한다. DB와 백업을 업무 자료로 관리한다. 이 작업에서 OpenAI·Microsoft Graph로 자료를 전송하지 않으며, Outlook 자체의 정상 서버 동기화는 별개다. `actorId`는 이력용 이름이지 팀 로그인 신원이 아니다.

원천은 `outlook_com`으로 표시한다. 로컬 StoreID의 별도 해시 공간과 EntryID의 해시를 사용해 Graph 자료 및 다른 저장소의 메일과 자동 병합하지 않는다. 다른 저장소로 이동하거나 프로필이 재구성되어 ID가 바뀐 메일은 별도 항목으로 나타날 수 있다. Internet Message-ID만으로 복사본을 합치지 않는다. 같은 ID의 내용·공급자 버전·폴더 정보·조회 기준이 바뀌면 새 버전을 보관하며 기존 업무에 연결한 이전 버전은 유지한다.

## 코드와 API

| 구성 | 책임 |
| --- | --- |
| `ariadne/outlook/local.py` | 폴더 선택 권한, 비동기 수집 작업, 입력 검증, 프로세스 경계, 기존 저장소 호출 |
| `ariadne/outlook/local_reader.ps1` | Windows PowerShell STA에서 Outlook COM을 읽는 고정 스크립트 |
| `ariadne/web/local-outlook.js` | 사서함·폴더 선택, 수동 실행, 상태 확인, 근거함 진입 |
| `ariadne/mail/models.py` | 기존 메일 계약에 로컬 원천 폴더·조회 기준 검증 추가 |

| 메서드·경로 | 입력·결과 |
| --- | --- |
| `GET /api/local-outlook` | 지원 환경·진행 작업·최근 작업 식별자 |
| `POST /api/local-outlook/discover` | `{requestId}` → 202, 폴더 조회 작업 |
| `POST /api/local-outlook/collect` | `{requestId,folderKey,basis,startDate,endDate,limit,actorId}` → 202, 수집 작업 |
| `GET /api/local-outlook/jobs/{id}` | 읽기/저장 단계, 신규·동일·변경·실패 건수, 일부 결과 표시 |

브라우저가 원천 StoreID·EntryID나 메일 본문을 제출하여 저장할 수 없다. 서버가 발급한 임시 폴더 키만 받으며 실제 원천 ID는 서버가 보관한다. 같은 요청 ID·조건의 재전송은 같은 작업으로 처리하고 조건이 바뀌면 거절한다. 프로세스당 한 작업만 수행하며 마지막 20개 작업을 메모리에 보관한다.

COM은 HTTP worker에서 직접 호출하지 않는다. 별도 Windows PowerShell 프로세스의 STA가 호출하고 결과를 JSON으로 돌려준다. 고정 스크립트는 인코딩하여 전달하며 사용자 입력은 JSON 표준입력으로만 전달한다. 셸 문자열 삽입·ExecutionPolicy 변경·프로필 스크립트 실행을 사용하지 않는다. 공급자 원문 오류·메일 본문을 로그에 남기지 않는다. 한국시간의 반개방 기간을 UTC로 변환한 후, Outlook DASL 날짜 문자열에는 PC의 지역 형식과 분 단위를 사용한다.

## 검증 기록

사용자가 2026-10-01 회사 PC의 클래식 Outlook에서 PowerShell 진단을 실행해 폴더·제목·본문·첨부파일명 접근 성공을 보고했다. 이는 COM 접근 가능성 검증이며 **이번 앱의 수집 버튼으로 실제 회사 메일을 저장한 인수 시험은 아직 아니다.** 실제 메일 내용·주소·첨부파일명은 테스트나 Git에 넣지 않았다.

[GitHub CI 실행 36804821748](https://github.com/bigpine-choi/ARIADNE/actions/runs/36804821748)의 8개 작업이 모두 통과했다. Linux/Windows × Python 3.12~3.14에서 각각 227개 테스트를 실행했다. Linux는 222개 통과·Windows 전용 5개 제외, Windows는 226개 통과·미지원 OS 전용 1개 제외다. 기존 207개에 서비스·HTTP·프로세스·Windows 스크립트 검증 20개를 추가했다. Windows에서는 실제 PowerShell 엔진에 합성 Outlook 객체를 공급해 받은/보낸 시각과 한국어/영어 지역 설정을 검증했다. 실제 Outlook 앱·회사 보안 정책 검증과 구분한다.

Chromium 31개 흐름(기존 25개·로컬 수집 6개), 기존 Godot 엔진 회귀, wheel에 최신 PowerShell·웹 자원이 포함되고 테스트 자료는 제외되는 것을 확인했다. 새 흐름은 폴더 선택·일부 수집, 반복 수집 중복 방지, 브라우저 새로고침 후 최근 결과, 안전한 본문 표시와 원천 정보, 서버 재시작 후 보존, 좁은 화면의 버튼 접근을 포함한다. 반복 실행 시 이전 완료 결과가 잠시 남던 화면 문제를 수정한 뒤 다시 통과했다. 검증한 코드 SHA는 `23f57a10a9cfde24d30e8230982e9b4e4835006f`이며 이후 커밋은 문서 갱신이다.
