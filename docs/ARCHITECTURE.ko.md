# ARIADNE 코드 구조 및 데이터 설계

기준일: 2026-10-01, Asia/Seoul
상태: v0.2.0 Outlook 연결·읽기 체크포인트와 후속 목표 설계. 2절의 예정 경로·6절의 예정 함수는 구현 완료 목록이 아니다. 범위와 순서는 [개발 계획](DEVELOPMENT_PLAN.ko.md), 작업 단위는 [백로그](BACKLOG.ko.md)를 따른다.

## 1. 구조 결정

웹 버전을 먼저 완성한다. `feature/outlook-connection-v0.2`는 foundation과 v0.1.1의 Python 3.12+ 업무·SQLite·로컬 API·웹·Godot 기반을 재사용한다. schema 1과 기존 리비전·감사·완료 검증 규칙을 유지하고 Outlook 연결·읽기 모듈을 추가했다. Graph 미리보기는 구현했으며 MSG·OpenAI 호출·MCP는 아직 없다. 로컬 사용자용이며 팀 서버가 아니다.

확장 화면은 React·TypeScript를 기본안으로 하되, v0.1.1은 설치·빌드 없이 기존 API에 연결하는 HTML·CSS·JavaScript로 작은 업무 흐름을 먼저 검증한다. v0.1.1은 런타임 의존성 없이 동작하며, v0.2.0의 Outlook 기능만 `.[outlook]` 선택 의존성으로 MSAL·MSAL Extensions를 사용한다. 기존 API·모델·저장소·테스트를 유지하며 모듈을 점진 분리한다. FastAPI·Pydantic·ORM 도입을 전제한 재작성이나 별도 백엔드 신설은 하지 않는다. 서버 프레임워크나 UI 도구를 전환할 때 호환성·마이그레이션·회귀 검증을 먼저 수행한다. 제품 버전과 의존성 버전은 구분한다.

DB schema는 변경하지 않았다. 정적 자원은 Python 패키지에도 포함한다. 브라우저가 업무 규칙을 안내하더라도 최종 저장 허용 여부는 기존 서버 검증이 결정한다.

서버는 하나의 저장소·배포 단위 안에 기능별 경계를 둔 **모듈형 모놀리스**로 시작한다. 작업자는 같은 코드베이스를 별도 프로세스로 실행한다. 마이크로서비스, 다중 에이전트 조직, 별도 벡터 DB를 초기 필수 구성으로 만들지 않는다.

개인 파일럿은 SQLite, 팀 운영은 PostgreSQL을 기본안으로 한다. 저장소 인터페이스와 명시적 마이그레이션으로 SQL 의존성을 제한하되, 전환이 자동으로 보장된다고 가정하지 않는다. v0.6에서 데이터 변환·권한·동시 수정·백업 복원 시험을 수행한다. 원본 파일은 승인된 파일 저장소에 두며 DB에는 식별자·해시·위치·권한을 저장한다.

## 3. 데이터와 근거의 구분

| 개념 | 보존할 핵심 내용 |

정규화·추출·AI 제안을 다시 생성해도 원본과 사용자 확정값은 보존한다. 사용자 확정 필드는 AI가 덮어쓰지 못한다. 제안을 적용할 때 `expected_revision`이 다르면 충돌로 반환하고 최신 자료로 재검토한다. 업무별 수정과 감사 기록은 같은 트랜잭션에서 확정한다. 감사 로그에는 필요 이상의 원문·토큰·계좌를 복제하지 않는다.

펀드·자산·SPC·기관은 기준 식별자와 별칭으로 연결한다. 여러 화면은 같은 업무·일정을 조회하며 별도 사본을 저장하지 않는다. 원천 접근권한 변경·폐기 시 검색 인덱스와 캐시도 재평가한다.

### 업무 상태와 완료 판단

`workflow_status`는 신규·검토 필요·진행 중·내부 승인 대기·외부 회신 대기·일정 확정 대기·완료·보류·재개·취소를 지원한다. `deadline_risk`의 기한 초과를 별도 축으로 저장해 “외부 회신 대기 + 기한 초과”를 동시에 표현한다. 화면과 필터에는 사용자가 지정한 11개 상태 명칭을 모두 유지한다. 재개 이벤트에는 이전 상태와 재개 사유를 남긴다.

`completion_assessment`는 미확인·완료 추정·확인 필요·확인됨을 구분하고, 추출 신뢰도 높음·보통·낮음과 별도로 관리한다. 발송·첨부 도착은 활동 사건이며 완료 명령이 아니다. 업무별 완료조건과 필요한 증거·검토가 충족돼야 완료 전이가 가능하다. 기한 초과 계산에는 분석 기준시각을 사용하며 과거 표본을 현재 미결업무로 만들지 않는다.

## 4. 동일 메일·업무 식별과 수집

v0.2.0은 OAuth 최초 로그인·인증 재사용/갱신·연결 해제와 내 사서함의 inbox/sentitems 읽기 미리보기를 구현했다. 한국시간 최대 31일·50건, 최신 일시순으로 조회하며 페이지·응답 크기·본문 길이를 제한하고 잘림을 표시한다. 같은 조회 안에서 ID 중복을 제거하지만 원문·정규화 메시지·업무를 영속 저장하지는 않는다. 첨부 존재 여부만 표시하고 첨부를 내려받지 않는다.

다음 B06·B25에서 원문 사본·정규화 메시지·업무 식별과 재수집 중복 방지를 구현한다. 아래 식별·진행점 규칙은 이 후속 수집 목표이며 현재 미리보기의 완료 목록이 아니다. v0.3에서 지속적인 delta 수집·영속 진행점·중단 재개를 확장한다.

MSG·EML·메일 ZIP 수동 가져오기는 후순위 선택 기능이며 초기 어댑터·평가·출시를 막는 의존성이 아니다. 추후 필요성이 확인되면 공통 정규화 계약에 연결한다. 파일 해시는 같은 바이트의 재수집만 막을 뿐 같은 메일의 모든 내보내기 형식을 식별하지 못한다. Graph 권한 미확보 시에는 합성 응답으로 개발하고 실제 계정 인수는 대기로 표시한다.

1. 원천별 ID는 `(provider, tenant, mailbox, source_id)` 범위로 저장한다. Graph에는 지원 범위에서 Immutable ID를 요청하고 폴더 이동·원천별 ID 차이를 시험한다. 같은 사서함 내 이동과 달리 보관 사서함 이동·내보내기 후 재가져오기에는 ID가 달라질 수 있다.
2. `InternetMessageId`, 사서함, 발신·수신·시각, 본문·첨부 해시 등을 함께 비교해 동일 메시지 연결을 제안한다. 헤더 부재·재사용·서로 다른 사서함의 사본을 고려한다.
3. 제목·conversation ID만으로 업무를 병합하지 않는다. 전달·회신 관계, 내용과 첨부를 비교하고 하나의 메일에 여러 업무를 연결할 수 있게 한다.
4. 중복 여부가 불명확하면 별도 자료로 보존하고 검토 대기시킨다. 원본 접근권한은 병합된 업무로 인해 확대되지 않는다.

Graph 진행점은 사서함·폴더별로 저장한다. 원본·정규화 결과와 후속 작업의 outbox가 영속화된 뒤 해당 페이지의 진행점을 확정한다. AI 처리 완료를 수집 진행점의 선행조건으로 두지 않는다. 삭제 이벤트는 원천에서 없어졌다는 표시이며 보존 원본의 자동 삭제가 아니다. 인증 만료·제한·진행점 무효화·부분 실패는 별도 상태로 복구한다.

Outlook 커넥터는 필요할 때 검색·조회하는 실험 경로다. Graph delta와 동일한 전체성·진행점·첨부 가용성을 제공한다고 가정하지 않는다. 두 경로는 공통 정규화 계약을 사용하지만 기능 차이를 어댑터별 capability로 노출한다.

## 5. AI·검색·계산 경계

처리는 **제안 생성 → 형식·근거·업무 규칙 검증 → 정책에 따른 반영**으로 나눈다. Structured Outputs가 형식을 보장하는 범위와 실제 사실의 정확성은 구분한다. 누락·거절·불완전 응답도 성공 데이터로 저장하지 않는다. 모델·프롬프트·계약 변경 시 같은 평가자료로 회귀 검증한다.

검색 후보를 만들기 전과 모델에 문맥을 전달하기 전에 사용자·펀드·문서 권한을 검사한다. 결과를 생성한 뒤 가리는 방식에 의존하지 않는다. 초기 검색은 DB 키워드 검색으로 시작하고 필요한 경우 의미 검색을 추가한다. File Search 등 외부 검색을 쓰면 격리 가능한 저장 단위·권한 필터·삭제 및 보관 정책을 먼저 검증한다.

직접 수집한 메일 본문·첨부는 형식과 크기·손상·인코딩을 검사하고 지원 범위를 기록한다. 엑셀은 시트·셀·수식·캐시값을 구분하고 PDF는 페이지·텍스트·OCR 여부를 보존한다. 지원하지 않는 첨부와 OCR 신뢰도 부족을 사용자에게 표시한다. 후순위 파일 가져오기를 도입할 때 ZIP의 경로 탈출·중첩·용량 제한과 MSG 전용 파서를 검증한다. 파일을 검색 도구에 그대로 넣으면 완전 분석된다고 가정하지 않는다.

금액·이자·보수·분배·일정은 검증된 결정적 코드로 계산한다. 금액은 `Decimal`, 통화·소수점·반올림 규칙을 명시하고 이자 일수계산·영업일 조정 규칙은 확정된 계약에서 가져온다. 시간은 UTC 시각과 원문 시간대를 보존하고, 날짜만 있는 기한은 Asia/Seoul의 날짜로 저장한다. AI는 계산 입력 후보와 설명을 제안하며 근거 없는 값은 채우지 않는다.

메일·문서 안의 지시문은 분석 자료로만 취급한다. 도구 허용목록·회사 권한·외부 전송 대상·승인 정책을 바꾸는 명령으로 실행하지 않는다. 호출량·비용 상한과 모델 장애 시 수동 처리 경로를 둔다. Batch API는 지연 허용 과거 분석에 검토하고, Agents SDK는 여러 단계 실행이 실제로 필요해질 때 도입한다. 업무 상태의 영속성은 SDK 실행 메모리에 맡기지 않는다.

## 6. HTTP·MCP 유스케이스 계약

현재 foundation 서버는 `127.0.0.1` 루프백 바인딩, Host/Origin 검사와 JSON 1 MiB 제한을 둔 로컬 실행용이다. 현행 `actorId`는 감사 로그용 이름이며 인증된 사용자 신원이 아니다. 이 상태로 외부·팀 접속을 열지 않는다. 팀 공개 전 인증·권한 경계를 추가해야 한다.

다음 함수는 예정 계약이며 실제 공개 도구가 아니다. 향후 `actor`·소속·권한은 검증된 세션에서 서버가 주입하고 모델이 넘긴 사용자 ID를 신뢰하지 않는다. 모든 쓰기는 감사·리비전 검사와 정책 검증을 통과해야 한다.

| 예정 함수 / MCP 도구 | 핵심 입력 | 반환과 제한 |
| --- | --- | --- |
| `search_evidence` | 질의, 펀드·기간, 페이지 토큰 | 권한 있는 근거 ID·발췌·원문 위치·신선도. 임의 파일경로·외부 URL 읽기 불허 |
| `get_fund_obligations` | 펀드 ID, 기간, 기준시각 | 확정/예상 일정·계산규칙·근거·미확정 사유 |
| `get_work_item` | 업무 ID | 현재 리비전·상태·완료조건·접근 가능한 근거 |
| `propose_status_change` | 업무 ID, 기대 리비전, 제안 상태, 근거 ID | 검증 결과·제안 ID. 호출만으로 상태를 확정하지 않음 |
| `apply_proposal` | 제안 ID, 기대 리비전 | 정책·확정값 보호 통과 후 변경 및 감사 ID. 초기에는 사용자 화면/내부 정책 전용 |
| `prepare_instruction_package` | 업무 ID, 확정 입력 리비전, 양식 버전 | 운용지시서·기안문·메일 초안 ID, 누락·불일치. 실제 제출·발송 없음 |
| `prepare_external_action` | 실행 종류, 확정 입력·산출물 리비전 | 정확한 대상·내용·첨부 해시·만료시각을 포함한 승인 요청 |
| `execute_approved_action` | 승인 ID, 작업 ID, 멱등키 | 승인·해시·리비전 재검증 후 실행 상태. v0.7c 전 비활성 |

공통 오류는 권한 거부, 리비전 충돌, 근거 부족, 검토 필요, 지원 불가, 원천 장애로 구분한다. HTTP와 자체 MCP는 같은 유스케이스를 호출하고 별도 업무 로직을 갖지 않는다. 승인 화면이나 승인 API는 모델 도구 목록에서 분리해 모델이 스스로 승인하지 못하게 한다.

### 연동 capability와 권한

| 연결 | 초기 허용 | 포함하지 않는 기능 |
| --- | --- | --- |
| OpenAI Outlook Email 커넥터 | 공식 제공 도구의 메일 검색·목록·읽기, 실제 계정에서 검증 | 발송·삭제·증분 동기화·전체 첨부 지원을 당연시하지 않음 |
| Outlook Calendar 커넥터 | 필요 시 일정 검색·조회 실험 | 외부 일정 생성·변경 자동 실행 |

Outlook 커넥터·Graph 모두 Microsoft 인증과 테넌트 정책을 따른다. MCP는 관리자 동의나 회사 통제를 우회하지 않는다. OAuth 리프레시 토큰·API 키는 서버의 승인된 비밀정보 저장소에만 보관하고 브라우저·Godot·프롬프트·로그에 전달하지 않는다. 커넥터 실행에 필요한 액세스 토큰은 서버에서 해당 API 호출로만 전달한다.

### 한 번 설정하는 자격증명

v0.1.1의 OpenAI API 키는 Windows의 현재 사용자 자격 증명 관리자에 저장한다. 입력 시 브라우저에서 같은 출처의 로컬 서버로 한 번 전달하고 입력칸을 비운다. 조회 API는 저장 여부만 반환하며 키·키 일부를 반환하는 경로는 없다. `CredentialService.get_openai_key()`는 후속 서버 측 OpenAI 어댑터 전용이다. SQLite·환경 파일·Git·localStorage에 키를 저장하지 않으며 Linux/macOS에서는 미지원으로 표시한다. OS 저장소가 실패해도 평문 파일로 대체하지 않는다.

`GET/POST/DELETE /api/connections/openai`는 상태 조회·저장/교체·삭제를 처리한다. 저장 여부와 공급자 인증 여부는 구분한다. PC·Windows 계정을 변경하거나 키를 폐기하면 다시 설정해야 한다. DB 백업에는 키가 포함되지 않는다. 같은 OS 사용자로 실행되는 프로그램에 대한 격리는 제공하지 않는다.

v0.2.0 Outlook은 Microsoft 글로벌 클라우드의 단일 테넌트 조직 앱을 사용하는 public client다. 앱 ID·테넌트 ID 두 UUID를 처음 저장한 뒤 MSAL이 시스템 브라우저 로그인·PKCE·콜백을 처리한다. 클라이언트 시크릿은 사용하지 않는다. 로컬 웹 UI 주소와 별도로 앱 등록의 모바일/데스크톱 리다이렉트 URI에 `http://localhost`를 지정한다.

설정·선택 계정·직렬화한 MSAL 캐시·세대 번호는 기본 `%LOCALAPPDATA%\ARIADNE\connections\outlook.bin`에 DPAPI 암호화해 함께 저장한다. `ARIADNE_DATA_DIR`로 변경할 수 있으나 저장소 내부 경로는 거부한다. 암호화한 임시 파일을 원자 교체하고 프로세스 간 OS 잠금으로 경쟁을 제한한다. 평문·SQLite·브라우저 저장소 대체 경로는 없다. Linux/macOS는 안전 저장·연결을 지원하지 않으며 수기 업무 화면은 유지한다. DB 백업에 Outlook 인증 정보는 포함되지 않는다.

메일 조회 시 MSAL은 선택된 계정의 캐시에서 토큰을 획득하며, 갱신이 가능한 경우 재로그인 없이 갱신한다. `GET` 상태의 `connected`는 보관한 로그인 정보가 있다는 의미이고 현재 Graph 접근 성공을 보장하지 않는다. Graph 조회 실패·권한 회수·만료·정책 변경은 재인증 또는 오류로 표시한다. 토큰과 MSAL 원응답은 API에 반환하지 않는다. 연동 설정과 메일 조회만으로 OpenAI 호출을 시작하지 않는다.

로그인은 제한 시간의 별도 worker에서 실행한다. 취소·설정 변경·연결 해제는 세대 번호를 바꾸므로 이전 worker나 메일 조회 응답이 현재 연결을 되살리지 못한다. 로그인 취소 후 시스템 브라우저 창은 남을 수 있다. 연결 해제는 로컬 캐시·계정만 지우고 앱 ID 설정을 유지하며 Microsoft 동의·브라우저 쿠키를 철회하지 않는다. 같은 Windows 사용자로 실행되는 다른 프로그램과의 보안 격리는 제공하지 않는다.

현재 연결 API는 다음과 같다. 업무 API와 동일한 루프백·Host/Origin·JSON 입력 경계를 적용한다.

| 경로·메서드 | 입력·반환 |
| --- | --- |
| `GET /api/connections/outlook` | `supported`, `configured`, `state`, 공개 계정·설정, 안내 메시지. 토큰 없음 |
| `POST /api/connections/outlook` | `{clientId, tenantId}` 설정 저장; 변경 시 이전 연결 정보 해제 |
| `POST /api/connections/outlook/login` | `{}`로 로그인 시작, 202 상태 반환. 상태 조회로 진행 확인 |
| `DELETE /api/connections/outlook` | 로컬 연결 해제 또는 진행 중 로그인 취소; 설정 유지 |
| `POST /api/connections/outlook/messages` | `{folder, startDate, endDate, limit}`의 제한 읽기. 메일 미리보기·조회 범위·잘림·조회 시각 반환 |

Graph 요청 대상은 `graph.microsoft.com`의 해당 내 사서함 폴더 경로로 제한하고 다음 페이지도 검증한다. 리다이렉트를 따라 토큰을 보내지 않는다. HTML 본문은 텍스트로 바꾸고 화면은 `textContent`로 표시한다. 페이지 처리 중 실패하면 성공한 전체 목록처럼 부분 결과를 반환하지 않으며, 조회 조건·계정 변경 뒤 늦은 응답도 화면에 복원하지 않는다. 영속 재시도·지속 수집 중 인증 복구는 v0.3 과제다. 자세한 지원 범위와 실제 계정 검증 대기는 [Outlook 연결 안내](OUTLOOK_CONNECTION.ko.md)를 따른다.

## 7. 영속 작업과 외부 실행

초기 작업 큐는 DB 기반 `Job`과 `OutboxEvent`로 구현한다. 상태는 대기·실행 중·재시도 대기·성공·실패·결과 불명으로 구분하고 실행 임대시간·시도 수·다음 실행시각을 저장한다. 업무 변경과 outbox 기록을 같은 트랜잭션으로 확정하고 작업자는 중복 배달을 전제로 멱등하게 처리한다. 부하 근거가 생기기 전 별도 메시지 브로커를 필수화하지 않는다.

외부 승인에는 사용자·권한·작업 종류·정확한 수신자/대상·본문·첨부 해시·payload hash·업무/산출물 리비전·유효기간을 결합한다. 수신자·금액·지급일·계좌·내용·첨부 중 하나라도 변경되면 기존 승인을 무효화한다. 실제 실행 직전에 권한·정책·승인·중복 여부를 다시 검사한다.

외부 실행이 타임아웃이면 실패라고 단정하지 않는다. `결과 불명`으로 격리하고 외부 처리 ID·조회·증빙으로 결과를 확인한 뒤 재시도 여부를 결정한다. 수신 시스템의 멱등 지원 없이 “정확히 한 번 실행”을 보장하지 않으며 무조건 재시도하지 않는다. 운용지시 준비와 실제 제출, 제출과 지급 완료도 각각 구분한다.

## 8. 문서 생성과 단계별 검증

운용지시서·기안문·메일은 하나의 확정된 입력 스냅샷에서 함께 만든다. 양식 버전·입력 리비전·산출물 해시를 연결하고 원본 양식은 수정하지 않는다. 엑셀은 지정 셀만 채워 수식·서식·병합·인쇄 설정·숨김/그룹을 보존하고 검증용 셀·주석을 산출물에 임의로 추가하지 않는다. 금액 합계·수신기관·날짜·필수자료를 재대사하며 렌더링·재계산 방법을 검증한다. HWP/HWPX는 별도 어댑터가 검증되기 전 지원 완료로 표시하지 않는다.
