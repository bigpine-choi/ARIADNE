# v0.2.1 메일 근거함 안내

기준일: 2026-10-01, Asia/Seoul. 개발 브랜치: `feature/mail-evidence-v0.2.1`.

Outlook에서 필요한 메일을 선택해 본문·첨부 목록을 보관하고 기존 업무의 근거로 연결한다. B06·B25 기초 체크포인트이며 첨부 내용 파서나 AI 업무 추출은 포함하지 않는다. 실제 회사 테넌트 로그인·메일 조회는 아직 검증하지 않았다.

## 설치·업데이트

Python 3.12 이상, Outlook 연결은 Windows와 기존 조직 계정 앱 등록을 사용한다. 최초 앱 등록·로그인·인증 재사용 절차는 [Outlook 연결 안내](OUTLOOK_CONNECTION.ko.md)를 따른다. 받은 저장소 폴더에서 실행한다.

```powershell
python -m pip install -e ".[outlook]"
python -m ariadne --db "$env:LOCALAPPDATA\ARIADNE\demo-web.sqlite3" serve --demo
```

<http://127.0.0.1:8765>에서 사용한다. 별도 Node 설치나 웹 빌드는 필요 없다. 가상 업무 추가 옵션인 `--demo`가 회사 메일을 자동 수집하지는 않는다.

**기존 DB를 사용한다면 업데이트 전에 이전 버전의 백업 기능으로 보관한다.** 시작 시 schema 1→2 전환을 트랜잭션으로 실행하며 기존 업무·사용자 확정값·근거·감사 이력을 유지한다. 전환 실패 시 전체를 되돌린다. schema 2로 전환한 DB는 이전 버전에서 열 수 없다. 이전 앱으로 돌아갈 때는 전환 전 백업을 사용한다. 실행 중인 SQLite 파일을 단순 복사하지 말고 앱의 백업 명령을 사용한다.

```powershell
# 업데이트 전, 실행 중인 이전 버전의 프로젝트 폴더에서 수행
python -m ariadne --db "$env:LOCALAPPDATA\ARIADNE\demo-web.sqlite3" backup "$env:LOCALAPPDATA\ARIADNE\before-mail-evidence.sqlite3"
```

## 메일 선택·저장

1. **연결 설정 → Outlook 연결 및 메일 읽기**에서 로그인하고 폴더·기간을 지정한다. 미리보기 범위는 받은 편지함 또는 보낸 편지함, 한국시간 종료일 포함 최대 31일·50건이다.
2. 필요한 메일의 **근거 저장 선택**을 체크한다. 한 번에 최대 10건을 선택하고 저장자 이름을 입력한다.
3. **선택한 메일 저장**을 누른다. 서버가 선택한 메일 본문·첨부 목록과 공급자 버전을 다시 확인하고 신규·변경 버전·기존과 동일 건수를 표시한다. 단순 조회만으로 저장하지 않는다.
4. 대화상자를 닫고 상단 **메일 근거함**을 연다. 제목·본문·발신자를 검색하고 저장 시점의 본문·첨부 목록·버전을 확인한다. 연결을 해제한 상태에서도 저장된 메일은 조회할 수 있다.

미리보기 선택 ID는 서버 메모리에만 10분간 유지된다. 최대 5개 조회·총 250개 메시지 ID를 보관하므로 오래된 조회는 다시 읽어야 한다. 계정·연결 설정 변경, 연결 해제, 서버 재시작 후에는 이전 조회의 저장 권한을 사용할 수 없다. 미리보기 이후 메일이 바뀌면 변경된 내용을 조용히 저장하지 않고 다시 조회하도록 안내한다. 실패 요청은 자동 재시도하지 않는다.

저장 시 서버는 메시지당 본문 100,000자·수신자 100명·첨부 목록 100개, 선택 결과 전체 2 MiB로 범위를 제한한다. 미리보기 본문 한도는 20,000자이므로 저장된 본문이 미리보기보다 길 수 있다. 본문·수신자·첨부 목록 일부만 확보하면 해당 잘림 표시를 보존한다. 첨부 메타데이터의 상태는 `not_downloaded`이며 파일 내용은 받지 않는다. 저장 준비·재조회에는 60초 제한을 적용하고 일부 항목 실패나 연결 변경 시 해당 선택 전체를 저장하지 않는다.

## 중복과 변경 버전

사서함 식별자는 테넌트·인증된 계정의 안정적인 ID로 정하며, 바뀔 수 있는 이메일 주소만으로 다른 계정을 합치지 않는다. 같은 사서함·Graph 원천 ID의 정규화 내용이 같으면 기존 메일·근거·버전을 재사용한다.

내용이 바뀌면 기존 버전을 수정하지 않고 새 버전과 새 근거를 만든다. 해시는 포착 시각을 제외하고 첨부 ID 순서를 정렬해 계산한다. 본문뿐 아니라 공급자 버전·폴더 등 보관 메타데이터 변경도 새 버전을 만들 수 있다. 해시 대상은 정규화한 본문·메타데이터이며 원본 MIME/EML 파일의 해시가 아니다. 이는 의미가 같은 메일·복사본·다른 원천 ID를 AI로 합치는 기능이 아니다.

**보관 버전**에서 이전 내용을 열 수 있다. 버전 1을 업무에 연결한 뒤 버전 2를 수집해도 업무의 근거는 버전 1로 유지된다. 새 버전을 쓰려면 해당 버전을 확인하고 별도로 연결한다. Outlook 원문 변경·삭제를 자동 추적하거나 보관 내용을 자동으로 삭제하지 않는다.

## 기존 업무에 연결

메일 상세에서 버전과 기존 업무를 고르고 변경자 이름·연결 사유를 입력한 뒤 **이 버전을 업무에 연결**을 누른다. 이력과 업무 버전이 갱신되며 다른 업무 필드·확정 기한·완료조건은 유지한다. 메일은 맥락 근거로 추가되므로 연결만으로 완료되지 않는다. 같은 근거를 같은 업무에 다시 연결하면 중복 이력이나 버전을 만들지 않는다.

다른 창에서 업무가 바뀌면 충돌을 표시하고 자동으로 덮어쓰지 않는다. **최신 업무 목록 불러오기**를 눌러 제목·버전을 검토한 뒤 직접 재시도한다. 입력한 변경자·사유는 유지한다. 연결 후 기본 업무 화면의 새로고침으로 확인하며, 메일 창이 기본 화면의 미저장 업무 수정을 자동으로 덮어쓰지 않는다.

업무의 **근거 자료 → 저장한 메일 보기**는 연결된 정확한 버전을 다시 연다. 메일·첨부명에 HTML처럼 보이는 문자가 있어도 텍스트로 표시하고 실행하지 않는다.

## 보관 위치와 남은 범위

메일 본문·주소·첨부 목록은 지정한 **SQLite DB와 DB 백업에 암호화되지 않은 형태**로 저장한다. Windows DPAPI로 암호화하는 Outlook 인증 정보와 별개다. DB·백업을 업무 자료로 관리하며 Git에 올리지 않는다. 연결 해제는 토큰을 지우는 동작이고 저장한 메일·근거·업무 연결을 지우지 않는다. 현재 개별 보관 메일 삭제 UI는 없다.

Outlook 연결은 기존 Windows 지원 범위를 따르며, 저장된 메일 검색·업무 연결은 Outlook 연결이 없는 환경에서도 같은 업무 DB를 사용한다. `actorId`는 감사 이력용 이름이며 팀 로그인 신원이 아니다. 서버는 로컬 개인 파일럿의 루프백 실행을 유지한다.

첨부파일 자체·PDF/엑셀 파싱·AI 추출·자동 업무 생성·메일 발송·자동 완료·delta 상시 동기화·공유 사서함은 이번 범위에 없다. MSG·EML·메일 ZIP 가져오기는 계속 보류한다. 다음은 저장된 근거를 사용하는 OpenAI 업무 후보 추출·사용자 검토다.

## API 계약과 코드

| 메서드·경로 | 입력·결과 |
| --- | --- |
| `POST /api/connections/outlook/messages` | 기존 `{folder,startDate,endDate,limit}`. 미리보기 응답에 서버 발급 `previewId` 추가 |
| `POST /api/mail/import` | `{previewId,messageIds,actorId}`만 허용. `{created,unchanged,revised,items:[{mailId,revision,evidenceId,outcome}]}` 반환 |
| `GET /api/mail` | 저장 메일 기본 목록 |
| `POST /api/mail/search` | `{query,limit,offset}`. 검색어 최대 200자·limit 1~50. `{items,total,limit,offset}` 반환 |
| `GET /api/mail/{id}` | 최신 상세 `{mail}`. 본문·첨부 목록·버전 목록·현재 버전에 연결된 업무 포함 |
| `GET /api/mail/{id}/revisions/{revision}` | 지정된 보관 버전 상세 `{mail}` |
| `POST /api/mail/{id}/link` | `{revision,workItemId,expectedVersion,actorId,reason}`. `{item,alreadyLinked,evidenceId}` 반환; 새 연결의 오래된 업무 버전은 409, 이미 연결된 근거의 재시도는 무변경 성공 |

본문·계정 신원을 클라이언트가 임의로 제출하는 저장 API는 없다. 검색어는 POST 본문으로 보내 주소창·요청 URL에 남기지 않는다. 기존 JSON·Host/Origin 검사를 적용하며 토큰 조회·첨부 다운로드 경로를 추가하지 않는다.

`outlook/capture.py`는 일시적인 선택 권한, `outlook/service.py`는 인증·연결 세대, `outlook/graph.py`는 제한 재조회, `mail/models.py`는 엄격한 정규화 입력 검증, `mail/repository.py`는 버전·중복·검색·업무 연결을 맡는다. HTTP와 웹이 별도 업무 저장 규칙을 만들지 않는다.

## 검증 기록

로컬 Linux/Python 테스트는 **207개 중 204개 통과·Windows 전용 3개 제외**다. Graph 합성 응답, 다른 계정·연결 변경·미리보기 만료·실패 시 전체 무저장, 중복·수정 버전, 기존 확정값·이력 보존과 전환 실패 롤백, 백업 복원, 실제 HTTP 입력·출처 경계를 포함한다. JavaScript 구문·공백 검사, `python -S` 기본 실행 점검, Godot 소스 회귀, wheel 빌드를 확인했다. wheel에 웹 자원 5개·메일 모듈이 포함되고 테스트용 서버는 제외된 것을 확인했다.

**[GitHub Actions 실행 36794164503](https://github.com/bigpine-choi/ARIADNE/actions/runs/36794164503)의 8개 작업이 모두 통과했다.** 검증 코드 SHA는 `890b3863203918219f8998ca9c364fde3bb33a2c`다. 이후 결과 기록 커밋은 문서만 변경한다.

- Linux·Windows × Python 3.12·3.13·3.14의 6개 환경에서 각각 207개 테스트를 실행했다. Linux는 204개 통과·Windows 전용 3개 제외, Windows는 206개 통과·미지원 OS 전용 1개 제외다. Windows DPAPI 저장·복원과 강제 종료 후 인증 저장소 잠금 복구도 다시 통과했다.
- 실제 Chromium에서 기존 업무 10개·Outlook 연결 7개·메일 근거함 8개, 총 **25개 브라우저 흐름이 통과**했다. 선택 저장·재수집 중복·안전한 본문/첨부명 표시·업무 충돌·중복 연결·변경 버전·근거 카드의 정확한 이전 버전 열기·연결 해제·두 차례 재시작을 포함한다.
- 기존 Godot 엔진의 화면·API·수정·이력·완료 차단·재시작 회귀도 통과했다. 실제 브라우저 실행 결과는 CI를 기준으로 한다.

이 검증은 합성 Microsoft 응답과 가상 자료를 사용했다. 실제 회사 계정·메일·키를 사용하거나 외부 AI 호출을 실행하지 않았다.
