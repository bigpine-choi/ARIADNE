# v0.2.0 Outlook 연결·읽기 안내

기준일: 2026-10-01, Asia/Seoul. 개발 브랜치: `feature/outlook-connection-v0.2`.

v0.1.1 웹 업무 화면에 Outlook 로그인·인증 재사용·메일 읽기 미리보기를 추가했다. **B11의 연결·읽기 체크포인트**이며 메일 근거 저장과 AI 추출을 포함한 v0.2 전체 완료를 뜻하지 않는다. 실제 회사 테넌트 로그인·관리자 승인·실사서함 조회는 아직 검증하지 않았다.

## 지원 범위

| 항목 | 현재 구현 |
| --- | --- |
| 실행 환경 | Python 3.12+·Windows·사용자 PC의 로컬 웹 서버 |
| Microsoft 계정 | 글로벌 클라우드의 조직 계정, 단일 테넌트 앱 등록 |
| 최초 설정 | UUID 형식의 애플리케이션(클라이언트) ID·디렉터리(테넌트) ID 저장 |
| 인증 | MSAL 시스템 브라우저 로그인·PKCE, 위임 `Mail.Read` |
| 인증 재사용 | Windows DPAPI 캐시, 메일 조회 시 토큰 재사용·가능한 자동 갱신 |
| 읽기 범위 | 로그인한 본인의 받은 편지함·보낸 편지함, 요청당 최대 31일·50건 |
| 일시 | 한국시간 기준 시작일 00:00부터 종료일 다음 날 00:00 미만, 종료일 포함 |
| 표시 | 제목·발신자·수신/발신 일시·텍스트 본문, 첨부 존재 여부·본문 잘림 |
| 저장 | 연결 설정·계정·토큰 캐시만 보관. 조회한 메일·첨부를 영속 저장하지 않음 |

개인 Outlook.com 계정, 다른 클라우드, 공유·위임 사서함, 사용자 지정 폴더, 첨부 다운로드, delta 상시 수집, 메일 발송·변경·삭제는 이번 범위에 없다. MSG·EML·메일 ZIP 가져오기는 후순위 보류를 유지한다. Linux/macOS에서는 기존 수기 업무 화면을 사용할 수 있으나 Outlook 안전 저장·연결은 지원하지 않는다. 미지원 환경에서 평문 파일로 토큰을 저장하지 않는다.

## 설치와 실행

해당 브랜치를 받은 폴더에서 Windows PowerShell로 실행한다.

```powershell
python -m pip install -e ".[outlook]"
python -m ariadne doctor
python -m ariadne --db "$env:LOCALAPPDATA\ARIADNE\demo-web.sqlite3" serve --demo
```

브라우저에서 <http://127.0.0.1:8765>를 열고 **연결 설정 → Outlook 연결 및 메일 읽기**로 이동한다. 별도 웹 빌드·Node 설치는 필요 없다. Outlook 의존성의 고정 버전은 `pyproject.toml`의 `outlook` 항목을 따른다. Outlook 없이 수기 업무만 사용할 때는 해당 선택 의존성을 설치하지 않아도 된다.

`--demo`는 가상 업무를 추가할 뿐 Outlook 로그인을 실행하거나 실제 메일을 읽지 않는다. `doctor`와 연결 상태 조회도 Microsoft에 접속해 인증을 시험하지 않는다. 서버 종료는 터미널의 `Ctrl+C`를 사용한다. 같은 업무 DB 경로로 재실행하면 기존 업무와 변경 이력이 유지된다.

## 최초 Microsoft 앱 등록

회사에서 허용한 앱 등록과 메일 읽기 권한이 필요하다. 기존에 승인받은 적절한 앱이 있으면 해당 등록 정보를 사용한다. 관리자 승인 화면이 나타나면 회사 절차로 승인을 받아야 하며 앱 코드에서 우회하지 않는다.

1. [Microsoft Entra 관리 센터](https://entra.microsoft.com/)의 회사 디렉터리에서 **앱 등록 → 새 등록**을 연다. 이름은 예를 들어 `ARIADNE Local`로 지정한다.
2. 지원 계정 유형은 **이 조직 디렉터리의 계정만**을 선택한다. 이번 구현은 테넌트 UUID를 사용하며 `common`, `organizations` 또는 개인 계정용 설정을 받지 않는다.
3. 등록한 앱의 **인증 → 플랫폼 추가 → 모바일 및 데스크톱 애플리케이션**에서 리다이렉트 URI **`http://localhost`**를 등록한다. 이 주소는 MSAL 로그인 콜백용이며 업무 화면 주소인 `http://127.0.0.1:8765`와 구분한다.
4. **API 권한 → Microsoft Graph → 위임된 권한**에서 `Mail.Read`를 추가한다. 이 앱은 사용자 본인의 본문 읽기를 위해 이 권한을 요청한다. `Mail.Send`·`Mail.ReadWrite`·애플리케이션 권한은 필요하지 않다. 회사 정책이 요구하면 관리자의 동의를 받는다.
5. 개요의 **애플리케이션(클라이언트) ID**와 **디렉터리(테넌트) ID**를 ARIADNE 설정에 입력하고 **설정 저장**을 누른다. 두 ID는 식별자이며 비밀키가 아니다. **클라이언트 시크릿을 만들거나 입력하지 않는다.**

앱 등록·URI 설정은 [Microsoft 앱 등록 안내](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app)와 [MSAL 토큰 획득 안내](https://learn.microsoft.com/en-us/entra/msal/python/getting-started/acquiring-tokens)를 기준으로 한다. Microsoft 화면 명칭은 표시 언어·관리 화면 개편에 따라 달라질 수 있다.

## 로그인과 다음 실행

**Microsoft 로그인**을 누르면 시스템 브라우저가 열린다. 회사 계정을 선택하고 필요한 인증·동의를 완료한다. ARIADNE는 로그인 상태를 주기적으로 확인한다. 비밀번호·MFA 코드를 ARIADNE 입력란이나 Git 설정에 넣는 흐름은 없다.

성공 후 화면의 **로그인 정보 저장됨 · 메일 읽기로 접근 확인**은 보관한 계정 정보가 있다는 뜻이다. 현재 메일 권한이나 토큰의 유효성을 보장하는 표시는 아니다. **메일 읽기**가 성공해야 해당 시점·조건의 실제 접근을 확인한 것이다.

같은 Windows 사용자·저장 위치로 재실행하면 ID를 다시 입력하지 않고 기존 계정의 캐시를 사용한다. 메일을 읽을 때 MSAL이 캐시에서 유효한 토큰을 찾거나 갱신한다. 권한 회수·조건부 액세스·MFA·갱신 만료 등으로 사용자 동작이 필요하면 다시 로그인한다. 항상 무인으로 갱신되거나 영구 연결된다고 보장하지 않는다.

로그인 대기 중 **로그인 취소**를 누르면 앱의 해당 로그인 요청을 무효화한다. 열린 시스템 브라우저 창은 직접 닫는다. 이전 로그인 worker가 끝나기 전에는 새 로그인 요청이 일시적으로 제한될 수 있다. 대화상자를 닫는 것만으로 로그인을 취소하지 않으며, 다시 열면 현재 상태를 확인한다.

## 메일 읽기

폴더·시작일·종료일·최대 조회 수를 고르고 **메일 읽기**를 누른다. 기본 조건은 최근 7일·20건이다. 받은 편지함은 수신 일시, 보낸 편지함은 발신 일시 기준으로 최신 항목부터 가져온다. 조회는 버튼을 눌렀을 때만 실행하며 자동 수집 스케줄은 없다.

- 제목을 펼쳐 텍스트 본문을 확인한다. 메일 HTML·이미지·스크립트를 실행하지 않는다.
- 본문은 메일당 최대 20,000자로 제한하고 잘렸으면 표시한다. 첨부가 있더라도 파일 자체는 받지 않는다.
- 페이지·건수·응답 용량 제한으로 일부만 보이면 기간을 좁혀 다시 조회한다. 제한된 미리보기를 사서함 전체 목록으로 취급하지 않는다.
- 같은 조회 안에서 같은 Graph 메시지 ID는 중복 표시하지 않는다. 이는 다음 버전의 영속 수집·재수집 중복 방지와 별개다.
- 조회 중 오류가 나면 이전 결과를 지우고 안내한다. 실패를 메일 없음으로 표시하거나 자동으로 재시도하지 않는다.
- 계정·설정·조회 조건 변경이나 연결 해제 뒤 도착한 오래된 결과는 화면에 복원하지 않는다.

현재 결과는 대화상자에서만 미리 보는 자료다. 업무 생성·완료 처리·근거 등록·AI 분석은 실행하지 않는다. 다음 B06·B25에서 원문·첨부 정규화와 근거 보존을 개발한다.

## 보관과 연결 해제

기본 보관 위치는 `%LOCALAPPDATA%\ARIADNE\connections\outlook.bin`이다. `ARIADNE_DATA_DIR`를 설정하면 그 사용자 데이터 경로 아래에 저장하며 소스 저장소 내부 경로는 허용하지 않는다. 설정·계정·MSAL 캐시·연결 세대 번호를 Windows 사용자 범위의 DPAPI로 함께 암호화한다. 암호화한 임시 파일의 원자 교체와 프로세스 간 OS 잠금으로 일부 저장·동시 변경을 처리한다.

브라우저 상태 API에는 공개 계정 정보·앱 ID·상태만 반환하며 액세스 토큰·리프레시 토큰·캐시 원문은 반환하지 않는다. 토큰을 SQLite·localStorage·평문 환경 파일·Git에 넣지 않는다. 같은 Windows 사용자 권한의 다른 프로그램까지 격리하는 저장소는 아니다.

**연결 해제**는 보관한 계정·토큰 캐시를 지우고 진행 중 로그인·조회 결과를 무효화한다. 앱 ID·테넌트 ID는 남겨 다시 입력할 필요를 줄인다. Microsoft 측 앱 동의 철회, 전 기기 로그아웃 또는 브라우저 쿠키 삭제와는 별개다. 다른 계정으로 연결하려면 해제 후 로그인 화면에서 계정을 선택한다.

SQLite 백업에는 Outlook 인증 정보나 기존 OpenAI 키가 포함되지 않는다. PC·Windows 계정·데이터 폴더가 바뀌면 다시 설정·로그인해야 할 수 있다. OpenAI 키는 기존 Windows 자격 증명 관리자에 별도로 보관하며 Outlook 연결 모듈과 공유하지 않는다.

## 검증 기록

- Linux Python 3.12.14에서 **135개 중 132개 통과, Windows 전용 3개 제외**를 확인했다. 제외 항목은 기존 Windows 자격 증명 관리자, Outlook DPAPI 저장, OS 잠금의 프로세스 종료 복구 검증이다.
- 테스트는 가상 인증·토큰·Graph 응답을 사용한다. 실제 계정·회사 메일·유료 OpenAI 호출은 사용하지 않았다.
- `python -S -m ariadne doctor`로 Outlook 선택 의존성이 없는 기본 실행 경로를 확인했다. 신규 Outlook 테스트는 인증 상태·캐시 재사용·해제 후 늦은 결과 차단·Graph 범위/페이지/오류/텍스트 처리·HTTP 입력 경계를 다룬다.
- [GitHub Actions 실행 36792445941](https://github.com/bigpine-choi/ARIADNE/actions/runs/36792445941)의 **8개 작업이 모두 통과**했다. 검증 코드 SHA는 `1027b64b0bb9c6124de291e2efb3170399627217`이다. 이후 결과 기록 커밋은 문서만 변경한다.
- Linux·Windows × Python 3.12·3.13·3.14의 6개 작업에서 각각 135개 테스트를 실행했다. Linux는 132개 통과·Windows 전용 3개 제외, Windows는 134개 통과·미지원 OS 전용 1개 제외다. Windows에서는 실제 DPAPI 암호화·대용량 합성 캐시 복원·연결 해제와 별도 프로세스 강제 종료 후 잠금 복구를 통과했다.
- CI의 실제 Chromium에서 기존 업무 화면 10개와 새 Outlook 7개 흐름, 총 **17개 브라우저 검증을 통과**했다. 새 흐름은 설정 유지, 로그인 취소·상태 갱신, 텍스트 미리보기, 조회 중 해제, 재인증, 실패 후 입력 보존이다. Outlook 서비스·메일은 합성 자료이며 실제 Microsoft 로그인은 하지 않았다. 기존 Godot 엔진의 화면·API·재시작 회귀도 통과했다.
- 로컬 wheel 빌드와 Outlook 모듈·웹 자원 4개 포함, 검증 fixture의 제품 패키지 제외를 확인했다. JS 구문·변경 공백 검사도 통과했다. 로컬 Chromium 다운로드는 환경에서 실패했으므로 브라우저 실행 결과는 위 CI를 기준으로 한다.
- 실제 회사 PC의 로그인·MFA·관리자 동의·Graph 메일 조회·사용성 검증은 대기 중이다. 합성 테스트나 Windows 보관 테스트 통과는 이 실계정 인수를 대신하지 않는다.

재현 명령:

```powershell

python scripts/check_godot.py
```

브라우저 개발 검증은 `.github/workflows/foundation.yml`의 Playwright·Chromium 설치 후 `node scripts/web_smoke.mjs`와 `node scripts/outlook_web_smoke.mjs`를 실행한다. 이 도구들은 제품 실행의 필수 설치 항목이 아니다.

## 코드와 후속 개발

인증은 `ariadne/outlook/auth.py`, 암호화 보관은 `store.py`, 프로세스 간 Windows 커널 잠금은 `locking.py`, 연결 수명과 충돌 제어는 `service.py`, 제한 읽기는 `graph.py`가 담당한다. 웹 `outlook.js`는 기존 업무 편집 화면과 분리한다. 업무 DB는 schema 1을 유지하며 메일용 스키마를 추가하지 않았다. API 계약은 [구조 설계](ARCHITECTURE.ko.md)의 연결 API 표를 따른다.

다음은 허용된 회사 계정에서 연결을 확인하고 B06·B25의 메일·첨부 정규화·근거 저장·중복 식별을 구현하는 것이다. 이후 저장한 OpenAI 키를 서버에서 사용해 업무 후보를 추출하고 사용자가 검토·확정하는 흐름으로 이어간다.

기술 참고: [MSAL 토큰 획득](https://learn.microsoft.com/en-us/entra/msal/python/getting-started/acquiring-tokens), [Microsoft 앱 등록](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app), [Microsoft Graph 메일 목록·페이지·본문 형식](https://learn.microsoft.com/en-us/graph/api/user-list-messages?view=graph-rest-1.0). 공식 기능 설명과 ARIADNE 실계정 인수 결과는 구분한다.
