# ARIADNE

AI가 메일과 문서를 계속 읽고 반복적인 정리·추적·준비를 처리하며, 사용자에게 판단과 승인이 필요한 업무를 모아주는 펀드 운용 업무 시스템입니다. 초기 기획명은 Fund Ops Workbench입니다.

**개발 방향: 웹 버전 먼저, Godot 클라이언트는 후속 확장.** 업무 규칙·데이터·API는 공통으로 사용하고, 웹의 핵심 업무 흐름을 검증한 뒤 Godot 화면을 별도로 개발합니다. 웹 버전은 계속 유지합니다.

**현재 상태: v0.1 1주차 기반 구현.** 업무·근거·일정 계약, SQLite 저장·변경 이력, 사용자 확정값 보호, 완료 증거 검사, 로컬 API·CLI와 Godot 시제품 코드가 있습니다. 웹 화면·팀 인증·중앙 서비스는 아직 없으며, Outlook 연동·MSG 파싱·실제 AI 추출·외부 실행과 회사 연결 조건 확인도 후속 작업입니다.

## 현재 기반 실행

Python 3.12 이상에서 소스 루트의 다음 명령을 실행합니다. 운영 기능에는 외부 Python 패키지가 필요하지 않습니다.

```powershell
python -m ariadne doctor
python -m ariadne serve --demo
```

서비스 주소는 `http://127.0.0.1:8765`이며 현재는 JSON API만 제공합니다. 브라우저 대시보드는 다음 구현 대상입니다. `--demo`는 가상 데이터만 추가하고 재실행 시 사용자 수정값을 보존합니다. DB는 기본적으로 소스 저장소 밖 사용자 데이터 폴더에 저장합니다.

기존 Godot 시제품을 확인하려면 `godot/project.godot`을 열고 F5로 실행합니다. 이는 후속 클라이언트 개발의 참고 기반이며 웹 버전 실행에 필요한 단계가 아닙니다.

- [1주차 구현·실행·데이터/API 안내](docs/V0_1_FOUNDATION.ko.md)
- [실제 검증 결과와 미검증 범위](docs/VALIDATION_V0_1.ko.md)
- [후속 Godot 클라이언트의 시제품·검증 기록](docs/GODOT_VALIDATION.ko.md)

검증: [CI 36739193704](https://github.com/bigpine-choi/ARIADNE/actions/runs/36739193704)에서 Linux·Windows의 Python 3.12/3.13/3.14 각각 42개 테스트와 Linux Godot 4.5.1 실제 실행·서비스 재시작 검사가 모두 통과했습니다. 이는 기존 기반과 Godot 시제품의 검사 결과입니다. 웹 화면 검증은 아직 없으며, Godot의 실제 Windows IME·화면 배치·Windows/Web 내보내기와 회사 계정 연동도 별도 검증 대상입니다.

```powershell
python -m unittest discover -s tests -v
python scripts/check_godot.py --source-only
```

## 제품 목표

- 새 요청, 기한 초과, 회신·승인 대기, 주요 위험을 자동으로 모읍니다.
- 펀드별 일정에 계약문서·조항·계산 규칙을 연결합니다.
- 업무 활동과 변경 이력을 자동으로 축적합니다.
- 근거가 충분하고 검증된 내부 정리 작업부터 자동 반영합니다.
- 사용자 확정값은 보존하고, 충돌하거나 불명확한 항목만 확인 요청으로 보냅니다.

메일 발송이나 첨부 수령만으로 업무를 완료 처리하지 않습니다. 외부 메일 발송, 외부 일정 변경, 원본 삭제, 자금집행·운용지시의 실제 실행에는 명시적 승인이 필요합니다. 초기 버전은 이들의 자료 준비와 검토를 지원합니다.

## 기술 방향

| 구성 | 계획 및 결정 상태 |
| --- | --- |
| 기본 화면 | 브라우저 웹 클라이언트를 우선 개발. 프레임워크는 구현 시 선택; 한글 입력·긴 목록·근거 열람·저장·재조회 검증 |
| 후속 화면 | Godot 클라이언트. 기존 시제품을 참고해 공통 API에 연결하며, 실제 사용성·Windows 실행·배포 방식은 확장 단계에서 검증 |
| 업무 처리 서비스 | Python 3.12+ 표준 라이브러리. 업무·근거·수정 제안·이력과 로컬 API 구현; 수집·AI·일정 계산은 후속 범위 |
| 개인 파일럿 저장 | SQLite 스키마 v1. 근거 메타데이터·추출 결과·제안·사용자 확정값·감사 이력 분리 |
| 팀 운영 | 승인된 중앙 서비스와 DB, 사용자별 접근권한. SQLite 파일을 공동 편집하지 않음 |
| 연동 | 과거 메일 파일 가져오기부터 시작하고 Microsoft Graph로 수신·발신 메일 증분 수집 |
| AI | 모델 교체가 가능한 연결 계층. 허용 자료와 검증 결과에 따라 선택하며 모델의 자신감만으로 실행 권한을 부여하지 않음 |

최종 목표는 팀이 공유하는 웹 대시보드입니다. 먼저 웹에서 메일 가져오기→업무 생성→원문 근거 확인→상태 수정→재조회·저장 보존을 검증합니다. 이후 Godot에서 추가 가치가 있는 상호작용·시각화를 개발하고 같은 API를 사용합니다. 웹 UI가 Godot UI로 자동 변환되는 것은 아니며, Godot 웹 내보내기는 웹 MVP의 선행조건이 아닙니다.

현재 로컬 API의 인증·권한·배포 기능을 보완해야 팀 운영이 가능합니다. 웹 클라이언트와 API를 같은 출처로 제공하는 경로부터 설계하고, 현재 루프백 서비스를 그대로 공개 배포하지 않습니다.

## 첫 구현 흐름

메일 가져오기 → 업무 생성 → 원문 근거 확인 → 상태 수정 → 재실행 후 보존.

기획 당시 자료 목록에는 메일 ZIP 5개 안의 `.msg` 523개와 주간업무회의 엑셀 3개가 기록돼 있습니다. 이는 중복 제거 전 파일 수이며 이번 1주차 코드에서 다시 집계하거나 본문·첨부를 분석한 결과가 아닙니다. 이번 구현·검증은 가상 데이터만 사용했습니다. 과거 자료를 오늘의 업무 현황으로 표시하지 않습니다.

원문 메일·계약서·첨부·연락처·계좌·투자자 정보·토큰은 Git 저장소에 올리지 않습니다. 실제 자료와 운영 데이터는 회사가 승인한 저장 위치에서 관리하고, 이 저장소에는 코드·문서·가상 또는 승인된 비식별 예제만 둡니다.
